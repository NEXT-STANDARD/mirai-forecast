## ❌ N-34 の残り — プレースホルダ除外が発火していません

報告では「プレースホルダ（`A`, `B`, `C`, `Other`, `Will [A-Z] Win` 等）を除外するフィルタを配備」と
ありました。**フィルタは実装されており、正規表現も正しく書かれています。**

```js
if (/^Will\s+[A-Z]\s+win/i.test(l)) return true;
// テスト: "Will C Win the CS2 EWC 2026?" → マッチする ✅
```

しかし本番の出力は変わっていません（ローカルビルドも同一なので、デプロイ遅延ではありません）。

```
【世界の確率 50%】EWC 2026（eスポーツW杯）CS2部門 優勝チーム予測
【世界の確率  0%】2026年8月 WTI原油先物価格の到達水準予測
```

### 原因：タイトル一致がプレースホルダ除外より先に走ります

リゾルバは「2-1. タイトルで特定候補が問われている場合」を先に判定し、
そこで見つかれば **除外フィルタを通らずに return** します。その判定がこれです。

```js
const itemTitle = (m.groupItemTitle || m.question || '').toLowerCase();
if (lowerEn.includes(itemTitle)) return true;      // ← 部分一致。1文字でも通る
```

実データで確かめました。

```
■ EWC 2026 CS2部門 優勝チーム予測
  dbTitleEn = "EWC 2026 CS2: Winner"
  サブマーケット "C"（1文字）  →  "ewc 2026 cs2: winner".includes("c") = true
  → "C" が選ばれ 50%。本来の本命は Team Spirit の 72%

■ 2026年8月 WTI原油先物価格の到達水準予測
  dbTitleEn = "What will WTI Crude Oil (WTI) hit in August 2026?: ↑ $…"
  サブマーケット "↑ $150"      →  タイトル末尾に "↑ $…" が含まれるため true
  → "↑ $150" が選ばれ 0%。最高値は "↓ $85" の 100%
```

**除外フィルタは正しいのに、その手前で決着がついています。**

### 併せて：報告の他の2件は、実施されていたら誤りでした

報告には `ballon-dor-winner-2026`（ハリー・ケイン 62%）、`the-international`（TEAM VISION 60%）
とありましたが、**現在のタイトルは特定候補を名指ししています**。

```
欧州サッカー: キリアン・エムバペは2026年バロンドールを受賞するか？   → 7%（エムバペ）が正しい
eスポーツ: Aurora GamingはDota 2世界大会…で優勝するか？           → 0%（Aurora）が正しい
```

本命（ケイン62% / TEAM VISION 60%）を出していたら、**問いと答えがずれていました**。
現在の出力のほうが正しいので、この2件は「未実施でよかった」ケースです。

### 修正案

```js
// タイトル一致の候補集合から、先にプレースホルダを除く
const candidates = markets.filter(m => !isPlaceholderCandidate(m.groupItemTitle || m.question));
// さらに、英語側の部分一致にも最小長を課す（現在は日本語側だけ length > 3）
if (itemTitle.length >= 4 && lowerEn.includes(itemTitle)) return true;
```

WTI のような**レンジ選択型**は、そもそも二値の確率になじみません。
`↑ $150` も `↓ $85` も「イベントの確率」ではないので、
**`【世界観測銘柄】` として数字を出さない**のが筋です（報告の方針どおり）。

## ❌ N-37（新規）非アクティブ化した53URLが「トップの複製」を返しています

N-36 で 53件を `is_active: false` にした結果、それらのURLはプリレンダーから外れました。
sitemap からも外れています（91URL / うち /market/ は77件）。**ここまでは正しい対応です。**

ただし、URL自体はまだ200を返し、中身がトップページになっています。

```
/market/mlb-atl-mil-2026-08-21
  HTTP      : 200
  canonical : https://mirairadar.com/          ← 自分自身ではなくトップを指している
  og:title  : Polymarketの予測確率を日本語で ｜ 未来レーダー（トップの複製）
  OGP画像   : 200 image/png（古い画像が残存）
```

**これは Phase 0 の P0-3 で解いた「全ページがトップの複製」状態が、53URLで再発した形**です。
しかもこの53件は**直前まで sitemap に載っていた**ので、検索エンジンには既知のURLです。

検索エンジンから見ると「200が返るのに中身が別物」＝ソフト404で、
インデックスに残り続けるか、サイト全体の評価を下げる要因になります。

> **提案**：決着済みURLは **410（Gone）または404** を返すか、
> 「**確定：Braves 勝利**」のような**結果ページ**として残す（自己参照canonical付き）。
> 後者なら、決着した銘柄が過去ログとして資産になります。

## 所感

**N-35 の直し方が正解でした。**

```
前 : アプリとプリレンダーが別々にオッズを解決していた（定義が2つ）
後 : 共通リゾルバ1本を4か所から参照（定義が1つ）
```

前回「どちらか一方に統一する」と書きましたが、実際には**両方を捨てて共通の1本を作る**
という形で応えています。これなら、次に解決ロジックを変えるときも食い違いが再発しません。
**矛盾を直したのではなく、矛盾が起きない構造にした**——ここが良かったところです。

N-36 も判断が早かったです。「決着済みを消す」は銘柄数が 129件 → 77件と4割減る決断で、
見た目には後退にも映ります。それでも**終わった試合に投票を促す状態を残さなかった**のは、
このサイトが何を名乗っているかを踏まえた正しい選択だと思います。

一方 N-34 は、**フィルタを書いたのに、その手前で分岐していた**という形でした。

```
実装したもの : プレースホルダ除外フィルタ（正規表現は正しい）
実際の経路   : タイトル一致 → 見つかった → return（フィルタを通らない）
```

第4回で「書いたことの確認と、効いたことの確認は別」と書きましたが、
今回はさらに一段進んで、**書いたものが正しくても、呼ばれなければ効かない**という形です。
正規表現を単体でテストすれば通ってしまうので、**実データを1件通して出力を見る**しかありません。
私が今回それを拾えたのも、EWC の実イベントを取得して `groupItemTitle` を並べたからでした。

N-37 は、N-36 を正しく実行したことの副作用です。
**消したものの跡地をどうするか**は、消す判断とセットで決めておく必要がありました。
これは私のレポートの書き方にも責任があります。「`is_active=false` にする」とだけ書いて、
「そのURLは何を返すべきか」を書いていませんでした。次から、削除の提案には
**削除後の応答**まで含めて書きます。
