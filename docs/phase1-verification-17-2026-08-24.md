## ✅ N-59 — 見出しが崩れていた

静的HTMLには N-49 で全ページに h1 を入れましたが、React が置き換えた後は崩れていました。

```
/            h1 なし（最初の見出しが銘柄タイトルの h2）
/forecast    h1 が「見習い観測員// Novice Observer」＝訪問者自身の称号
/embed/…     h1 なし（iframe 内の独立した文書なのに見出しが無い）
```

**訪問者の称号が h1 なのは、無いより悪い**です。ページが何であるかを、称号が名乗ってしまいます。

### あわせて序列の逆転も直した

```
修正前  h1 → h2(銘柄1件) → h3(セクション) → h4(銘柄群)
修正後  h1 → h2(銘柄1件) → h2(セクション) → h3(銘柄群)
```

**銘柄1件がセクション全体と同格**でした。飛びが無いので第16回の検査は通していました。

CSS はクラス基準（タグ名指定は共通リセットのみ）なので見た目は不変です。
実測でフォントサイズ・余白・ウィジェット高さ・横スクロールなしを確認しました。
本番で可視見出し43件・飛び0件です。

## ✅ N-60 — 検査が母集団の4割を見ていなかった

前回の所感にこう書きました。

> 「どの面を見ているか」を検査自身に書かせるような仕組みがないと、この型は止まらない気がしています。

調べたら、**検査自身が8ファイルの固定リストを持っていました**。

```
固定リスト : 8ファイル
実際に描画 : 13ファイル   ← 5ファイルが検査外
```

検査は「**全8コンポーネント統一性**」と名乗りながら、母集団の4割を見ていませんでした。
N-52（固定 slug 一覧）とまったく同じ形です。

### 実害が出ていました

```
投票0件の銘柄ページ（本番実測）
  日本世論支持率   受付中 (0票)      ← ガードが効いている表示
  世論スプレッド    世論観測中 (n=0)   ← 同上
  日本世論 YES: 50%                  ← ❌ MainTradingChart（ガード無し）
```

**50% は投票ゼロ時の既定値**です。この案件が何ラウンドもかけて OGP とプリレンダーから
消した「無言の50%」が、**固定リストの外側で生き残っていました**。

### 4面を直しました

| 面 | 状態 |
|---|---|
| MainTradingChart | 「0票」と「YES 50%」を並記していた → n≥3 ガード |
| ForecastHubPage | 同上 → n≥3 ガード |
| OrderBookConsensus | 開示条件が**「投票したか」だけ**だった → サンプル数も見る |
| MobileStickyVoteBar | 同上 → サンプル数も見る |

後ろの2つは、**自分の1票しかない銘柄でも乖離が出る**状態でした。
N-56 で埋め込みを直したのと同じ錯覚——「自分のクリックで世論が見えた」——を、
別の場所で作っていたことになります。

管理画面はカテゴリ規則で除外しました。運用者は n=1 の銘柄も見る必要があります。
**除外の取りこぼしは過検出になるだけで、defect を通す向きには倒れません。**

## ❌ N-61（新規・次ラウンド）— ハイドレーション後に description が捏造される

N-60 の確認中に、**同じ「既定値の漏れ」がもっと悪い場所で見つかりました**。

```
世界オッズ「取得なし」・投票0件の銘柄
  プリレンダーHTML : 日本の世論は集計中（n=0）      ← 正しい
  ハイドレーション後: 【世界オッズ YES 50% vs 日本世論 YES 50%】…  ← ❌ 両方とも既定値
```

クライアントの SEO ヘルパーが description を上書きし、**JSON-LD（ItemPage）にも
同じ値を入れています**。プリレンダーが正しく抑制した値を、クライアントが捏造で塗り替える形です。

世界オッズと投票がある銘柄では**正しく上書きされます**
（実測：「世界オッズ YES 0% vs 日本世論 YES 50%」＝実表示と一致）。
つまり**値が既定値のときだけ嘘になります**。

**影響範囲は広い**です。有効銘柄のうち **53件が n<3** なので、大半の詳細ページが該当します。

そして **Check #30（4面の主語一致）は静的HTMLしか見ていない**ので、
この上書きを通していました。Check #28 が h1 で通したのと同じ blind spot です。

### 目に見える方の漏れも1箇所

```
🟢 強気派  実現・強気シナリオ   ← hasWorldOdds でガード済み（数字を出さない）
🔴 慎重派  世界 NO 50%          ← ❌ ガード無し
```

同じウィジェットの左右で扱いが違います。

## 所感

前回の宿題に、思っていたより素直な答えが出ました。
**「面を取りこぼす」の原因は、検査が母集団を人の記憶から受け取っていたこと**です。

固定リストは書いた瞬間は正しく、時間とともにだけ間違っていきます。
しかも間違い方が悪い。**検査は緑のまま、見ていない面が増えていく**。
N-52（固定 slug 一覧）で一度これを踏んでいて、そのとき直したのは1箇所だけでした。
**同じ形が別の場所に残っていないかを、あのとき探すべきでした。**

破壊テストの4番目——新しいファイルを1つ置く——は、
今後この型の検査を書くたびに当てるべき試験だと思います。
「いま正しいか」ではなく「**足したときに勝手に入るか**」を試すものだからです。

そして今回も、パターン検索の12件をそのまま報告しかけました。
実害は1件でした。**grep の件数は候補の数であって、欠陥の数ではありません。**
第15回で「列挙は検査にやらせる」と書きましたが、
**列挙させた結果をそのまま信じるのも別の誤り**です。導出は母集団を作るためのもので、
判定は実測でやる。この2つは役割が違います。
