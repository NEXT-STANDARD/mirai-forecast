## ✅ N-49 — 静的HTMLが白紙でした

### 見つけ方

別のエージェントが追加した `/about` を検証していて、トップに `/about` へのリンクが
無いことに気づきました。「リンクが足りない」と思って全数を測ったら、
**そもそも全ページにリンクが1本も無い**ことが分かりました。

```
sitemap 79URL の静的HTML（JSを実行しない状態）
  <a href> が 0本 : 78件
  <a href> が 1本以上: 1件   ← ガイド記事だけ
```

`<body>` の中身を見たら、答えは明快でした。

```html
<body><div id="root"></div></body>
```

**本文0文字。** 銘柄ページも、トップも、`/about` も、全部これでした。

### なぜ11ラウンド見逃したか

P1-3 で「解説記事の `<a href>` が0件」を指摘し、修正しています。
**そのとき直したのは記事1本だけでした。** 同じ欠陥がサイト全体にあることを、
指摘した側も修正した側も確認していません。

これまでの検査は `<head>`（title・description・canonical・og・JSON-LD）を
すべて見ていました。**`<body>` を見る検査が1つも無かった**ので、
28項目に増えるまで誰も気づきませんでした。

### 直し方

アプリは `createRoot` を使っています（`hydrateRoot` ではない）。
`createRoot().render()` はマウント時にコンテナを空にするので、
**`#root` の中に静的本文を置いても不整合は起きません**。起動後に置き換わるだけです。

```
有効銘柄     : h1 ＋ 世界/日本の確率 ＋ 同カテゴリ5銘柄 ＋ サイト内ナビ
決着アーカイブ: h1 ＋ 説明 ＋ いま予測できる銘柄5件 ＋ ナビ（noindex, follow の follow 先）
固定ページ   : h1 ＋ description ＋ 注目銘柄5件 ＋ ナビ
トップ       : h1 ＋ リード ＋ 銘柄12件 ＋ ナビ（計17本）
404          : h1 ＋ 出口リンク（JSが失敗したときの唯一の導線）
```

トップは `staticPages` に入っておらず、**Vite の出力のまま素通りしていました**。
`baseHtml` として読まれるだけで、サイトで最も重要なページが白紙でした。

### 実機で確認したこと

ハイドレーション後、静的シェルは跡形もなく消えます。

```
static_shell_left : false        （シェルのテキストは残っていない）
shell_style_left  : false        （シェルの <style> も消える）
rootFirstTag      : DIV.min-h-screen bg-primary …   （アプリが正常にマウント）
sampleLinkColor   : rgb(248,250,252)                 （シェルの #7dd3fc は漏れていない）
コンソール         : Reactの警告・不整合エラーなし
```

## ⚠️ 検査自身の弱点を2つ潰しました

**破壊テストBを設計している最中に、自分の検査が穴だらけだと分かりました。**

### 穴1：ナビの文字列だけで文字数を満たす

当初の Check #28 は「本文80字以上」を見ていました。
ところが**ナビのリンク文字列だけで80字を超えます**。
h1も本文も空のページが、ナビだけで合格してしまう状態でした。

```
修正前 : body 全体の文字数を数える
修正後 : <nav> を除いて数える ＋ h1 が4字以上あることを必須にする
```

### 穴2：見た目の改善が、検査を黙って弱めた

Tailwind の preflight で見出しもリンクも素の文字に潰れるため、
シェル内だけに効く `<style>` を足しました。**その CSS が本文としてカウントされていました。**

```
<style>#root h1{font-size:1.5rem;…}</style>
  → タグを剥がすと「#root h1{font-size:1.5rem;…}」が本文80字に算入される
```

**別の理由で入れた変更が、自分の検査を無言で無効化していた。** これが今回いちばん怖い発見です。
`<style>` も `<script>` と同様に除去し、**修正後にもう一度 破壊テストB を当てて**
検査が依然として働くこと（72件で FAIL）を確認しました。

## ❌ 残る2件はどちらもユーザー操作です

### 本番404

未知URLが **200** でトップを返します。3パターンで確認しました。

```
/__definitely_not_a_page__  → 200
/market/__nope__            → 200
/guide/__nope__             → 200
```

`404.html` 自体は正しく出来ていて、正しく配信されています。

```
/404.html → 307 → /404 → 200
  h1     : ページが見つかりません
  robots : noindex, follow
  リンク : 11本
```

**ファイルは正しいのに、未知URLでは使われていません。** Cloudflare Pages の
SPA フォールバック設定が `404.html` より優先されています。
`_redirects` では 404 を返せない（301/302/303/307/308 のみ）ことは実測済みなので、
**プロジェクト設定を切り替えるしかありません。**

#### ただし放置しても重複ペナルティは起きません

ソフト404の canonical はすべて `https://mirairadar.com/` を指しています。
検索エンジン側ではトップに統合されるため、Phase 0 で解いた
「全ページがトップの複製」という状態には戻っていません。**急ぎではありません。**

> なお N-49 で未知URLの中身が「白紙」から「トップの本文」に変わりました。
> 見かけ上それらしくなりますが、canonical の防御が効いているので実害はありません。
> 悪化していないことを実測で確認しています。

## 所感

今回の発見は、**別のエージェントが追加した `/about` を検証しにいって、
ついでに気づいた**ものです。狙って探したわけではありません。

「トップに /about へのリンクが無い」→「他のページからは？」→「全ページ0本」→
「そもそも本文が無い」と、**測るたびに問題が大きくなりました**。
最初の1歩は「リンクが1本足りない」でしたが、着地は「サイト全体が白紙」でした。

P1-3 で同じ欠陥を指摘しておきながら、記事1本だけ直して終わっていたのが原因です。
**指摘は「この記事にリンクが無い」で、修正も「この記事にリンクを足す」でした。**
どちらも間違っていませんが、**「他はどうか」を誰も聞かなかった**。
1件見つけたら母集団を測る、というのは第14回（監査期）で一度学んだはずのことでした。

そして今回いちばん効いたのは、**破壊テストを設計する行為そのもの**でした。
検査は書いた時点で28/28 PASSしていて、見た目には完成していました。
「どう壊せば落ちるか」を考え始めて初めて、
**ナビの文字列で合格してしまう**ことと、**自分が足した `<style>` が検査を弱めていた**ことが見えました。

検査を書いたあとに製品を触ったら、検査をもう一度壊してみる。
**製品の変更は、検査の前提を黙って壊すことがあります。**
