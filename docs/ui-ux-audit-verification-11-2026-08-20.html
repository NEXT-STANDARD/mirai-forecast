NEW-8 — ヘッダーが sticky 指定なのに固定されない

NEW-8高 「スクロール追従するヘッダー直下に配置」は成立していない
スクロール位置 3000px の時点 ヘッダー : position: sticky / top: 0px（指定はある） ヘッダーの実位置 : -3000 〜 -2902px ← 画面外へ流れている カテゴリバーの位置 : -2950 〜 -2903px ← 同上

15,000px 超のページで、一度スクロールするとカテゴリ切り替えに戻れません。 初期表示での到達性は確保されましたが、「追従」は成立していません。

原因（src/index.css:7525-7531）

html, body, #root { max-width: 100vw !important; overflow-x: hidden !important; /* ← これが sticky を無効化している */ position: relative; width: 100%; box-sizing: border-box; }

overflow-x: hidden を指定すると、仕様上 overflow-y が auto に昇格し、 html / body / #root がスクロールコンテナになります。 position: sticky はビューポートではなくそのコンテナを基準にするため、固定されません。 実測でも3階層すべてが overflow: hidden auto になっていることを確認しました。

検証済みの修正案

overflow-x を hidden から clip に変えると解決します。ブラウザ上で実際に試しました。

変更前 ヘッダー : -3000px（画面外） 変更後 ヘッダー : 0 〜 98px ← 固定された ✅ カテゴリバー : 50 〜 97px ← スクロール中も見える ✅ 横スクロール : 0px ← hidden の目的も維持 ✅

clip はスクロールコンテナを作らないため、sticky を壊さずに横スクロールだけを抑止できます。 hidden を clip に置き換える1語の変更で足ります。

なお、この CSS ブロックは監査開始時点から存在しており、ヘッダーは一度も固定されていませんでした。 今回カテゴリをヘッダーに戻したことで、初めて実害として表面化した形です。

D と E は私の報告に書いていない手口です。それでも検知できたのは、 strictGuardPattern がガード条件の構造そのものを検査しているからで、本物の強化です。

残る穴：0 && が素通りする理由

const strictGuardPattern = /(?:event|item)\.isExpired\s*\|\|\s*\(.../; // 部分一致 const falsifiedPattern = /false\s*&&\s*(?:event|item)\.isExpired/; // ブラックリスト 照合結果を実際に確かめました 正常 strict:一致 falsified:見逃し → PASS（正しい） false && で無効化 strict:一致 falsified:検知 → FAIL（正しい） 0 && で無効化 strict:一致 falsified:見逃し → PASS（★素通り）

strictGuardPattern は文字列のどこかにcanonical な条件式があれば通ります。 {0 && event.isExpired || (...) は canonical 部分をそのまま含むため一致してしまい、 接頭辞の 0 && は false && 限定のブラックリストに引っかかりません。 null && undefined && !1 && なども同様に通ります。

修正案：ブラックリストではなくアンカーで

// { の直後に isExpired が来ることを要求する const strictGuardPattern = /\{\s*(?:event|item)\.isExpired\s*\|\|\s*\(\s*(?:event|item)\.endDate\s*&&\s*new Date\(...\)\s*\)/; // これなら falsifiedPattern（ブラックリスト）自体が不要になります
