NEW-9 は実用上、解消しました。ヘッダー背後の文字の透けは消えています。

ただし、報告されている解消の理由は成立していません。

「vite.config.ts に cssTarget: 'chrome90' を指定 → 本番ビルド後の CSS に backdrop-filter: blur(20px) が確実に保持されることを確認」

ビルド後の CSS を確認したところ、ヘッダーには依然として無印プロパティが入っていません。 実際に効いているのは、同時に行われた 背景不透明度 0.96 への変更のほうです。 原因は別のところにあり、1行の並べ替えで直ることを実証しました。

cssTarget は、ヘッダーには効いていない

NEW-9原因の切り分け 根本は「宣言の順序」だった
/* dist/assets/index-*.css */ .header-container-slim{z-index:40;-webkit-backdrop-filter:blur(20px);background:#020617f5;...} ↑ -webkit- のみ。無印は入っていない

cssTarget: 'chrome90' を外してビルドしても結果は同じでした。

cssTarget あり → -webkit-backdrop-filter のみ cssTarget なし → -webkit-backdrop-filter のみ

ただし cssTarget が無意味だったわけではありません。 ファイル全体では無印プロパティが 7 箇所残っています。 効かなかったのはヘッダーを含む特定の2ルールだけです。

原因：宣言の順序

ルール宣言順ビルド後
.header-container-slim（232行）無印 → -webkit-❌ -webkit- のみ
モーダル（1829行）無印 → -webkit-❌ -webkit- のみ
他5ルール無印のみ✅ 無印が残る

esbuild の CSS 最適化は、この2つを同等の宣言として畳み込み、後に書かれたほうを残します。 ソースが 無印 → -webkit- の順なので、標準プロパティが捨てられていました。

検証済みの修正：順序を入れ替えるだけ

-webkit-backdrop-filter: blur(20px); backdrop-filter: blur(20px); /* ← 後に置く */ 結果 → .header-container-slim{...backdrop-filter:blur(20px)...} ✅ 無印が残った 無印プロパティ総数 7 → 9

ベンダープレフィックスはプレフィックス版を先、標準版を後に書くのが慣例で、その形に直すだけです。 該当は 2 箇所（232-233行 / 1829-1830行）のみです。

検証後、index.css は diff で完全一致を確認して復元しています。 なお背景が 0.96 になった今、blur が無くても実害は出ていません。急ぐ修正ではありません。

所感

利用者から見た問題は解決しています。ヘッダーの透けは消え、sticky も安定しています。

ただし今回は、「直った理由」が報告と違いました。 cssTarget を足したこと自体は無駄ではありませんが（他5ルールには効いています）、 ヘッダーに関しては効いておらず、実際に効いたのは背景不透明度のほうです。 cssTarget を外してビルドしても出力が同じだったことで、これは確定しています。

これは責めるような話ではなく、原因の切り分けが1段浅かったというだけです。 「ビルド後の CSS に無印プロパティが無い」→「ターゲット設定の問題だろう」と推定したが、 実際は同一ルール内の宣言順という、もう一段下の話でした。

こういうときに効くのが、まさにこのプロジェクトで整備してきた検証の型です。

推定で直す → 直ったように見える 実測で確かめる → 直った理由が違うと分かる

ビルド後の CSS を1回 grep すれば分かる話でした。 自己検証エンジンに「.header-container-slim に無印 backdrop-filter が存在すること」を 1行足しておけば、この種の推定違いも自動で拾えます。

check #8 の精密化は、指摘（過検知の懸念）を正確に受け止めた良い修正でした。 検知力を落とさずに誤検知だけを消しており、3種のテストすべてで期待どおりに動いています。

残る3件は構造リファクタリングのみです。とくに index.css が 1万行を超えたので、 B-3 は「いつかやる」から「そろそろやる」に移ってよい頃だと思います。
