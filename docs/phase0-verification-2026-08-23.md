## 🔴 N-19（新規・最優先）全銘柄の詳細ページが開かない

### 症状

```
https://mirairadar.com/market/brazil-presidential-election/
  <title>       タルシシオ・デ・フレイタスは…（正しい）
  OGPカード      正しい（銘柄名・確率入り）
  実際に表示される内容   ❌ トップページ（52枚の銘柄カード＋乖離ランキング）
```

4銘柄で確認し、**すべてトップページに着地**しました。

| slug | 表示された内容 |
|---|---|
| `brazil-presidential-election` | ❌ トップページ |
| `putin-out-before-2027` | ❌ トップページ |
| `ballon-dor-winner-2026` | ❌ トップページ |
| `openai-gpt5-release-2026` | ❌ トップページ |

原因が決定論的なため、**120銘柄すべてが該当**します。

### 原因：末尾スラッシュとルーティング正規表現の不整合

プリレンダーが `dist/market/<slug>/index.html`（ディレクトリ形式）で出力しているため、
Cloudflare Pages は `/market/<slug>` に **307リダイレクト**をかけて `/market/<slug>/` に送ります。

```
curl -I https://mirairadar.com/market/brazil-presidential-election
→ HTTP/2 307
→ location: /market/brazil-presidential-election/
```

一方 `src/App.tsx:66` のルーティングは末尾スラッシュを想定していません。

```js
const match = window.location.pathname.match(/^\/market\/(.+)$/);
```

実際の挙動を再現しました。

```
/market/brazil-presidential-election    → 抽出: "brazil-presidential-election"    ✅
/market/brazil-presidential-election/   → 抽出: "brazil-presidential-election/"   ❌ スラッシュ込み
```

スラッシュ込みの slug は DB に存在しないため、`detailMarketId` が解決できず、
アプリはトップページにフォールバックします。

### これは Phase 0 が生んだ回帰です

| | `/market/<slug>` の挙動 |
|---|---|
| **Phase 0 前**（本日午前の実測） | HTTP **200** ／ SPAが**詳細ページを表示** ／ OGPは汎用 |
| **Phase 0 後**（現在） | HTTP **307** → `/market/<slug>/` ／ SPAが**トップを表示** ／ OGPは正しい |

**OGPは直り、中身が壊れました。** 共有カードは完璧に見えるのに、
クリックした人は求めた銘柄にたどり着けません。シェアを増やす施策としては逆効果になります。

### 修正案

**主案：プリレンダーの出力形式を変える（推奨）**

```
dist/market/<slug>/index.html   →   dist/market/<slug>.html
```

Cloudflare Pages は `.html` を拡張子なしのパスで **200配信**します（リダイレクトなし）。
これなら **URL体系が Phase 0 前と完全に同じ**になり、

- App.tsx の変更が不要
- canonical / og:url / sitemap が宣言している「スラッシュなし」と実URLが一致する
- sitemap 133件の307がすべて解消する

**併せて（防御的に）：正規表現を末尾スラッシュ耐性にする**

```js
const match = window.location.pathname.match(/^\/market\/(.+?)\/?$/);
```

`App.tsx:66` と `App.tsx:231` の2箇所。こちらだけでも症状は消えますが、
307と canonical の不一致は残るため、**主案と併用**を推奨します。

**受け入れ基準**：`curl -sI https://mirairadar.com/market/<slug>` が **200**（307でない）で、
かつブラウザで開いたときに `.market-detail-container` が存在すること。**120件全数で確認してください。**

## ⚠️ URL形式の不一致（N-19 と同根）

宣言と実体が食い違っています。

| 要素 | 形式 |
|---|---|
| 実際に200を返すURL | `/market/<slug>/` （スラッシュ**あり**） |
| `canonical` の宣言 | `/market/<slug>` （**なし**） |
| `og:url` の宣言 | `/market/<slug>` （**なし**） |
| sitemap の120件 | `/market/<slug>` （**なし**） |

sitemap 全133URLのHTTPステータスを実測しました。

```
HTTP 200 :   8件   （トップ、カテゴリ付きトップ、/api/mcp）
HTTP 307 : 125件   ← sitemap のほぼ全部がリダイレクト
```

canonical が「リダイレクトするURL」を指している状態です。Google は最終的に解決しますが、
**canonical はリダイレクトしない最終URLを指すべき**とされています。
N-19 の主案（`.html` 形式）を採れば、これも同時に解消します。

## 🔄 自己訂正：私の計測ミスが2件ありました

### ① 「n<3 なのに日本世論を含む 5件」は誤りでした

最初の全数スキャンで5件の違反を検出しましたが、**私が Supabase から `id` を取得していなかった**ためです。
投票ログは `event_id`（数値ID）で記録されており、slug だけで突き合わせると票数が0に見えます。

`id` を含めて再計測したところ、**違反は両方向とも0件**でした。
検出した5件は、むしろ**正しく n≥3 と判定されている銘柄**でした。

### ② 「OGP画像チェックは破壊テストを通らない」も誤りでした

生成を1件スキップしたのに PASS したため「検知できない」と判定しかけましたが、
**私が削除したPNGと、生成をスキップした銘柄が別物**でした
（スキップ対象は生成側の並び順で決まるのに、私は自分の取得順の先頭を消していた）。

スキップされた slug を出力させ、同じ銘柄のPNGを消してから測り直したところ、
**正しく FAIL を検知**しました。

これで私の計測ミスは**7件目**です（oklch未対応／翻訳判定／行番号ずれ／母集団がトップのみ／
破壊テスト後の再ビルド漏れ／今回の2件）。

## 所感

**P0-1〜P0-5 の作りは良かったです。** とくに JSON-LD で `n≥3` ガードを守った点は、
言われたことをやるだけでなく**方針を理解して適用している**証拠です。
新規チェック3件が破壊テストを通ったのも、第14〜16回の経緯を踏まえた変化だと受け取りました。

一方 N-19 は、**「直った」と「使える」が別だった**という話です。

```
OGPカード      → 完璧になった
検索の下地      → 整った
リンクをクリック → トップページに飛ばされる
```

出口を塞いでいた3つの配線を通した結果、**その先の扉が閉まった**形です。
プリレンダーをディレクトリ形式で出した瞬間に URL が変わる、という副作用が見えていなかった。

再発防止として、③のチェック追加を強く勧めます。
「生成されたか」は見ているのに、「**それを開いたら何が表示されるか**」を誰も見ていませんでした。
私のロードマップの受け入れ基準にも、そこが抜けていました。**これは私の設計不足です。**
