## ❌ P1-3 — 内部リンクが「リンク」になっていない

### 症状

記事から関連銘柄への導線は**表示され、クリックもできます**。
しかし `<a href>` ではなく `<div>` のクリックハンドラで実装されています。

```
記事ページ /guide/polymarket-japan
  <a href> の数            : 0
  関連銘柄の表示            : ✅ FRB・日銀・GPT-5 の3件が描画されている
  クリックしたときの挙動     : ✅ /market/fed-decision-in-september-762 へ遷移した
```

**これはサイト全体の実装です。**

```
トップページ
  <a href> の数     : 0
  銘柄カード         : 28枚（すべて <div class="market-card-item">）
  ヘッダーのナビ      : すべて <button>
```

### なぜ問題か

P1-3 の目的は「**123枚の銘柄ページを、入口ページの補強に使う**」ことでした。
そのためには検索エンジンがリンクを辿れる必要があります。

```
人間     : クリックできる    → 問題なし
クローラ : リンクが存在しない → 辿れない
```

現状、銘柄ページは **sitemap 経由でしか発見されません**。
内部リンクによるクロール優先度・評価の受け渡しがゼロです。

これは Phase 1 で作り込まれたものではなく、**SPA の初期からの実装**です。
ただし P1-3 の受け入れ基準（「記事から3件以上の銘柄へリンクし、すべて200」）は満たしていません。

### チェックが通ってしまった理由

追加された検査は、`relatedMarketSlugs` の**データ妥当性**を見ています。

```js
// 関連記事リンクが有効銘柄に実在すること (P1-3)
const relatedMatch = guideSource.match(/relatedMarketSlugs:\s*\[([\s\S]*?)\]/);
if (rawSlugs.length < 3) { … }
for (const slug of rawSlugs) { activeEvents.some(...) }
```

**「3件以上あるか」「その slug が実在するか」は見ていますが、
「`<a href>` として出力されているか」は見ていません。**
チェック名が「内部リンク整合性」なので、実態より広く読めてしまいます。

### 修正案

**主案：銘柄カードとナビを `<a href>` にする**

```jsx
// 現在
<div className="market-card-item" onClick={() => navigate(slug)}>

// 提案
<a href={`/market/${slug}`} className="market-card-item"
   onClick={(e) => { e.preventDefault(); navigate(slug); }}>
```

`preventDefault` + `pushState` で SPA の挙動は今のまま保てます。
クローラは `href` を読み、人はSPA遷移する、という両立ができます。

**併せて：チェックを実体に合わせる**

`dist/guide/polymarket-japan.html` ではなく、**描画後のDOM**で
`a[href^="/market/"]` が3件以上あることを見る必要があります。
プリレンダーHTMLには本文が入らないため、静的検査では不可能です。

> **補足**：影響は記事だけではありません。トップの28枚のカードも同様なので、
> 修正すればサイト全体の内部リンク構造が一度に立ち上がります。

## ✅ 記事の内容 — 法務対応は丁寧です

仕様の「厳守事項」は**すべて守られています**。

| 厳守事項 | 実際の記述 |
|---|---|
| 法的助言をしない | 「本解説は…**法的助言を構成するものではありません**。個別の法解釈…必ず弁護士等の専門家にご相談ください」 |
| 法解釈は出典を明示 | 「**パークス法律事務所の公開整理等**によれば」 |
| 回避方法を書かない | 「**VPN等を用いて地理制限を迂回する行為は利用規約違反および法令違反リスクを伴うため推奨されません**」と明確に非推奨 |
| 競合を貶めない | ポイ活型を「月間100万人規模」と事実として併記（Bloomberg出典つき） |
| 売り込みは1箇所 | 第4節のみ |

**「使ってよい事実」6項目もすべて出典つきで正しく使われています。**
構成も指定した5節どおりです。

### 2点だけ、気になる記述があります

**① 自サイトの結論として「合法」と断定している箇所**

> 「情報インテリジェンスツールとしては**合法的に**閲覧・参照することができます」

閲覧行為が問題になる可能性は実務上ほぼ無いと思いますが、
仕様では「『違法です』『合法です』と自サイトの結論として断定しない」としていました。
**「制限の対象外です」「閲覧は制限されていません」**のような事実の記述に寄せると、
記事全体の姿勢（法解釈は引用に留める）と一貫します。

**② 出典のない精度主張が2箇所**

> 「数億ドルのリアルマネーが投じられた**極めて精度の高い**集合知データ」
> 「予測市場の確率は既存の世論調査やアナリスト予想を**凌駕する精度を示してきました**」

これは事実の主張ですが、出典がありません。
そして**このプロジェクトが14ラウンドかけて守ってきた姿勢と噛み合いません**。
`n<3` なら乖離を出さない、という規律を敷いているサイトが、
自分に有利な精度主張は無根拠で書く、という形になっています。

出典を付けるか、「精度が高いとされる」程度に緩めるかの**どちらかを推奨**します。

## ⚠️ 自己検証が一度だけ 17/2 になりました

その後3回連続で 19/19 に戻り、再現しません。

**原因は件数の競合と考えられます。** 検証中、有効銘柄が増え続けていました。

```
セッション中の推移 : 123件 → 126件 → 127件
```

件数一致を見るチェック（sitemap件数・プリレンダー数・有効銘柄数）は、
**ビルドが件数をスナップショットした後に銘柄が追加されると、偽陽性で FAIL します**。

日次の銘柄生成が動いている以上、CI で時々赤くなる可能性があります。
実害はありませんが、「たまに落ちる検査」は信頼を損ねます。
**件数の完全一致ではなく「プリレンダーに無い有効銘柄が存在しないこと」**
（＝片方向の包含関係）で判定すると安定します。

> なお、この 17/2 について**どの2件が落ちたかは記録できていません**。
