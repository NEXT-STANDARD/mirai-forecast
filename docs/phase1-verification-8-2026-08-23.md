## ❌ N-35（新規・重要）アプリとプリレンダーが違う数字を出しています

同じ銘柄について、**ページ本文とOGPカードが最大100ポイント食い違います。**

| 銘柄 | アプリ本文 | OGP・プリレンダー | 差 |
|---|---:|---:|---:|
| `what-price-will-wti-hit-in-august-2026` | **100%** | **0%** | **100** |
| `fed-decision-in-september-762` | **69%** | **0%** | **69** |
| `ballon-dor-winner-2026` | **61%** | **7%** | **54** |
| `the-international-2026-winner` | **53%** | **0%** | **53** |
| `ewc-2026-cs2-winner` | **72%** | **50%** | 22 |
| `bitcoin-up-or-down-on-august-23` | 61% | 59% | 2（時間差） |
| epl-bri-ast / bitcoin-above / mlb-atl-mil / atp-gombos | 一致 | 一致 | 0 |

**10件中6件が不一致。**

### 原因：2つの「世界オッズ」の定義が並立しています

多肢イベント（1イベントに複数のサブマーケット）で、両者が別のものを選んでいます。

```
アプリ      : 最大値／本命を採る
プリレンダー : タイトルに一致するサブマーケットを採る
```

FRB で確かめました。

```
イベント「Fed Decision in September?」（サブ5件）
  「Will the Fed decrease interest rates by 50+ bps?」 =  0%   ← 当サイトのタイトルと一致
  「Will there be no change in Fed interest rates?」   = 69%   ← 最大値

当サイトのタイトル : 米FRB：9月FOMCで50bp以上の大幅利下げを実施するか？
  アプリ表示      : 69%  ← 「変更なし」の確率。問いが違う
  OGP表示         :  0%  ← 正しい
```

**この銘柄については、プリレンダー側が正しく、アプリ側が誤りです。**

読者にとっては、ページで69%を見て、それをXに貼ると0%のカードが出ます。
**どちらを信じればいいのか分からない**状態になっています。

> **提案**：どちらか一方の解決関数に統一する。タイトルが特定候補を指すなら
> 「タイトル一致」が正しく、指さないなら**そもそも数字を出さない**のが筋です。

## ❌ N-36（新規）決着済みの銘柄を「世界の確率」として出しています

直接取得（`/events/{id}`）に **`closed` のフィルタがありません**。
同期の一覧取得は `active=true&closed=false` で絞っていますが、こちらは素通しです。

Polymarket に107件（数値ID）を照会しました（対照：FRBは実データ／存在しないIDは404）。

```
API応答あり         : 99件
  closed=false（取引中）: 46件
  closed=true （決着済）: 53件   ← 本番では「世界の確率」として表示中

確率が 0% または 100% : 67件
  うち closed=true    : 50件
```

決着済みの例です。

```
100%  テニス公式戦: Norbert Gombos vs Radu Mihai Papoe   （closed=true）
  0%  MLB公式戦: Washington Nationals vs. Texas Rangers  （closed=true）
100%  MLB公式戦: New York Mets vs. Chicago White Sox     （closed=true）
```

**終わった試合が「予測」として並び、しかも投票を促されます**（「受付中（0票）」「あなたの1票で世論オッズ解禁」）。

DBの `end_date` は 08/27・08/29 など未来です。これは Polymarket の**清算期限**であって
試合の終了時刻ではないため、既存の期限チェックでは捕まりません。

> **提案**：`closed=true` の銘柄は `is_active=false` にする（または「確定」として別扱いにする）。
> 0%/100% が67件（過半）という分布そのものが、予測サイトとして不自然な状態を示しています。

## ❌ N-34 の残り — 勝者選択型で `leaderName` が null

0%クランプの撤廃は効いています（辞書の1%が **398件 → 8件**）。
本命抽出も入りましたが、**発火したのは1件だけ**でした。

```
isMultiChoice = true               : 94件
  leaderName あり（【世界本命】表記）:  1件

```

93件の多くは**タイトル一致が効いている**ので実害はありません
（例：「Prague 2: Gombos vs Papoe」はタイトルと対応）。
問題は**タイトルが「どれが勝つか」を問う型**のときです。6件あり、うち3件が実質無意味でした。

| 銘柄 | 表示 | 実際に採られたサブマーケット | 妥当性 |
|---|---:|---|---|
| EWC 2026 CS2部門 優勝チーム予測 | **50%** | 「Will **C** Win the CS2 EWC 2026?」 | ❌ プレースホルダ。本命は Team Spirit 75% |
| 2026年8月 WTI原油 到達水準予測 | **0%** | 「WTI hit **(HIGH) $150**」 | ❌ 26水準のうち1つ |
| イングランド・プレミアリーグ 優勝クラブ予測 | **50%** | 「Will **Arsenal** win」 | ❌ 1クラブの確率 |
| パリ・サンジェルマンは…優勝するか？ | 14% | 「Will Paris Saint-Germain win」 | ✅ 一致 |
| シナーは…優勝するか？ | 0% | 「Will Jannik Sinner win」 | ✅ 一致 |
| Aurora Gaming は…優勝するか？ | 0% | 「Will Aurora Gaming Win」 | ✅ 一致 |

**辞書には `isMultiChoice: true` が入っています。** フラグは持っているのに、
`leaderName` が null のときは黙って `【世界の確率】` として出しています。
ここは **`isMultiChoice && !leaderName` なら数字を出さない**のが安全です。

## 所感

**Check #14 の直し方が、今回いちばん良かったところです。**

```
前 : observedProbs.length >= 20 が「前提条件」   → 全滅すると判定に入らない
後 : observedProbs.length >= 35 が「要件」       → 全滅でも部分欠落でも落ちる
      ＋ 取得0件ならビルドを throw で停止
```

私が書いた「症状ではなく原因に紐づける」を、そのまま形にしています。
破壊テストを2段階（完全欠落・部分欠落）で組んだところ、どちらも意図どおり落ちました。
**再発防止テストとして、ここは完成しています。**

N-32 の「取得なし（取引量僅少）」も、チャートまで一緒に消しているのが良い判断でした。
数字だけ消してグラフが残っていたら、結局は架空のデータを見せることになります。

一方で N-35 は、**修正の速さが生んだ副作用**に見えます。
アプリ側とプリレンダー側を別々に直した結果、「世界オッズとは何か」の定義が2つできました。

```
アプリ      : そのイベントで最も確からしい結末は何か（最大値）
プリレンダー : この見出しの問いに対する答えは何か（タイトル一致）
```

**どちらも一理ありますが、同時に存在してはいけません。**
そしてこの矛盾は、片方だけを見ている限り絶対に見つかりません。
私が今回それを拾えたのは、**同じ銘柄を2つの経路で測ったから**です。
一つの数字が複数の場所に出るなら、**その場所の数だけ測る**——これは次から手順に入れます。

N-36 は、カバー率を上げにいったことの裏返しです。
`closed` を外して取得範囲を広げたら、**終わった試合まで入ってきた**。
0%と100%が67件（過半）という分布は、それ自体が異常のサインでした。
**分布を見る**のは、値の正しさを1件ずつ追うより早く異常に気づけます。ここも手順に足します。
