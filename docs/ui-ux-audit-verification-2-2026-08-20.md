## 4. 🆕 今回新たに発見した問題（3件）

### NEW-1 【実害あり】PWA バナーが利用規約・プライバシーポリシーのリンクを覆い、クリックを奪う

モバイルでページ最下部までスクロールすると、PWA バナー（`z-index: 1000` / 343×217px）が
**新設したフッターリンクの真上に重なります。**

```
利用規約              重なり 39×26px    中心が奪われている: true
プライバシーポリシー   重なり 120×26px   中心が奪われている: true
```

`document.elementFromPoint` でリンク中心を叩くと **PWA バナーが返る**＝タップしてもリンクは反応しません。

PWA バナーは「スクロール 400px 超」で表示される仕様のため、
**フッターに到達した時点で必ず表示されており、必ず重なります。**
G-2（規約リンクの新設）の効果を、D-3対応（PWAバナーのスマート化）が打ち消している形です。

**対策**: バナー表示中はフッターに下部余白を足す、またはバナーをフッター到達時に自動的に隠す。

### NEW-2 【開発体験】dev サーバーでは spacing ユーティリティが効かない（本番のみ正常）

同一コードで、**`vite build` の出力と `vite dev` の出力が異なります。**

| | `* { margin:0; padding:0 }` の所属 | `pb-16` | `p-3` | `text-world` |
|---|---|---|---|---|
| **本番ビルド（4173）** | `@layer base` | **64px** | **12px** | **rgb(56,189,248)** |
| **dev サーバー（5173）** | **★レイヤー外★** | **0px** | **0px** | 継承色 |

dev 側はサーバー再起動＋`node_modules/.vite` 削除後、新規タブでも再現します。
`src/index.css` のソース自体は `@layer base { * {...} }` と正しく書かれており、
`/src/index.css` が返す CSS 文字列でもレイヤー内にあるため、
**Vite の dev 用 CSS 注入経路のどこかで `@layer` が失われている**と考えられます。

**実害**: 利用者に届く成果物は正常なので、本番影響はありません。
ただし開発者はローカルで余白が崩れた画面を見ることになり、
**「まだ直っていない」と誤認して不要な修正を入れる**リスクがあります。第1回検証で私自身が踏んだ落とし穴でもあります。

**対策**: 判定は必ず `vite build` → `vite preview` で行う。
併せて `@config` / `@layer` の扱いを Tailwind v4 のドキュメントで確認し、dev でも一致させる。

### NEW-3 【軽微】`pb-16`（64px）より固定バー（81px）のほうが高い

`pb-16` は 64px、モバイル固定バーの実測高は 81px。差分 17px。
実機では隠れるテキスト要素は 0 件で実害は出ていませんが、余白がバー高より小さい構造は残っています。
バー高は D-4 の銘柄名追加で 71 → 78 → 81px と伸び続けているため、`pb-24`（96px）か
`padding-bottom: calc(81px + env(safe-area-inset-bottom))` のような明示指定が安全です。

### 参考（軽微）: 2行クランプで文が途中で切れる

`spread-ai-text` は `line-clamp: 2` ですが `display: flow-root` のため
`-webkit-line-clamp` の省略記号が出ず、`text-overflow: clip` で文が途中で断ち切られます
（85文字中、約2行分のみ表示・実測 `scrollHeight 105px` vs `clientHeight 35px`）。
C-1 の文字拡大で1行あたりの文字数が減った分、切れ方が目立つようになりました。
