### 原因：末尾の数字を落とす前方一致

`EmbedWidgetPage.tsx` の照合条件です。

```js
const match = events.find(
  (e) => e.slug === slugOrId
      || e.id === slugOrId
      || e.slug.replace(/-\d+$/, '') === slugOrId.replace(/-\d+$/, '')   // ← これ
);
```

末尾の `-<数字>` を落として比較するため、`official-*` 系はすべて同じ文字列になります。

```
official-1787044209435 → official
official-1787046116414 → official
official-1787046120279 → official
official-1787044205330 → official
official-1787044213329 → official
official-1787046123636 → official
official-1787048081444 → official
official-1787048085663 → official      ← 8件すべて "official" に潰れる
```

`Array.find()` は**最初に当たった要素**を返すので、8件とも配列の先頭にある `official-*` が返ります。

| `official-1787046120279` | **0票** | サンプル収集中 (n=0) | **⚡ 乖離: 17% GAP (n=3)** |

### Supabase の URL と anon キーが Functions にハードコードされている

`functions/market/[slug].ts` と `functions/topic/[slug].ts` に、
プロジェクト URL と anon キーが**リテラルで**書かれています。

```ts
'apikey': 'eyJhbGciOiJIUzI1NiIs…'      // ← anon キー（JWT の role を確認済み）
```

JWT を復号して確認したところ **`role: anon`** で、`.env` の
`VITE_SUPABASE_ANON_KEY` と同一でした。**これはクライアントバンドルにも入る公開鍵**なので、
新たな漏洩ではありません（`service_role` は含まれていません）。

ただし、

- 鍵をローテーションするとき、`.env` と Functions の2箇所を直す必要がある
- このリポジトリの規約（秘密情報は環境変数から読む）から外れる

ので、`context.env.SUPABASE_URL` / `context.env.SUPABASE_ANON_KEY` に寄せておくのが素直です。
**急ぎではありません。**
