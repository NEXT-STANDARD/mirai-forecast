## ❌ N-28（新規）MLB と テニスに「欧州サッカー」が付いています

### 症状

本番に「欧州サッカー:」で始まる銘柄が17件あります。**そのうち13件はサッカーではありません。**

```
欧州サッカー: Atlanta Braves vs. Milwaukee Brewers 勝敗予測        ← MLB
欧州サッカー: New York Mets vs. Chicago White Sox 勝敗予測         ← MLB
欧州サッカー: San Francisco Giants vs. Cleveland Guardians         ← MLB
欧州サッカー: Los Angeles Angels vs. Texas Rangers 勝敗予測        ← MLB
欧州サッカー: Chicago Cubs vs. Seattle Mariners 勝敗予測           ← MLB
欧州サッカー: Prague 2: Norbert Gombos vs Radu Mihai Papoe         ← テニス
欧州サッカー: Cancun: Sebastian Baez vs Lloyd Harris 勝敗予測      ← テニス
欧州サッカー: Sion: Lorenzo Giustino vs Benjamin Hassan 勝敗予測   ← テニス
欧州サッカー: Monterrey Open, Qualification: Maya Joint vs …       ← テニス
```

**内訳：野球9件・テニス4件。** 正しく欧州サッカーなのは4件（エルチェCF×2・ニューカッスル・バロンドール）だけです。

### 原因

`translateFallback` の終盤に、**"vs" を含めば何でもサッカーにするキャッチオール**があります。

```js
if (/vs\.?|対/i.test(t) && !t.startsWith('LoL') && !t.startsWith('CS2')) {
  let clean = …;
  if (/Lynx|Valkyries/i.test(t)) return { titleJa: `WNBA公式戦: ${clean} 勝敗予測`, … };
  return { titleJa: `欧州サッカー: ${clean} 勝敗予測`, category: 'sports' };   // ← ここ
}
```

MLB用のルールはチーム名の**ハードコード列挙**です。

```js
/Dodgers|Rockies|Orioles|Rays|Cardinals|Reds|Tigers|Pirates|Marlins|Phillies|Yankees|Red Sox/i
```

この12球団に入っていない **Nationals・Rangers・Mets・White Sox・Braves・Brewers・Giants・
Guardians・Athletics・Royals・Angels・Cubs・Mariners** は、全部キャッチオールへ落ちます。
テニスも `Cincinnati Open:` と `ITF M25` しか個別対応がないので同じです。

> **これは今回の変更で入ったものではありません。** `0eeae9c` の1つ前にも同じ行があります。
> ただ、英語タイトルが片づいた結果、いま最も目立つ誤りになりました。

### 直し方の提案

キャッチオールの既定を「欧州サッカー」ではなく**中立**にするのが素直です。

```js
return { titleJa: `対戦カード予測: ${clean}`, category: 'sports' };
```

競技を当てにいくなら、ハードコード列挙ではなく**Polymarket側のタグ**（`c.cat` や
イベントのカテゴリ）を先に見るほうが、球団が増えても壊れません。

## ❌ N-29（新規・潜在）`Inter` が "The International" を拾います

サッカー判定に語境界がありません。

```js
/Elche CF|Newcastle United|Barcelona|Real Madrid|Manchester|Liverpool|
 Arsenal|Chelsea|Bayern|Dortmund|Juventus|Inter|Milan/i
```

`Inter` は部分一致なので、**"The International"** にマッチします。実測しました。

```
英語タイトル : Will Aurora Gaming Win The International 2026?
サッカー式   : true   （拾った語 = "Inter"）
eスポーツ式  : true
現在の表示   : eスポーツ: Aurora GamingはDota 2世界大会「The International 2026」で優勝するか？
```

いまは `DIRECT_MAP` に id が登録されていて先に効くため、表示は正しいままです。
しかし**サッカー判定はeスポーツ判定より前に置かれている**ので、
`DIRECT_MAP` に無い "The International" 系の銘柄が来たら「欧州サッカー」になります。

**直し方**：`\bInter\b` のように語境界を付ける。あわせて `Milan`（Milanković など）や
`Arsenal`（一般名詞）も同じ形です。

## ❌ 上書きは止まりました。流入は止まっていません

永続性テストの最中に、**新しい英語銘柄が1件入りました。**

```
[economy] 経済・市場予測: Will Brighton & Hove Albion FC win on 2026-08-23?
```

ブライトンはプレミアリーグのクラブですが、サッカー判定の列挙に入っていないため
フォールバックのプレフィクスが付き、カテゴリも `economy` になっています。

この形のタイトルは `Will ` を含むのでガードの「綺麗」判定に入らず、**毎回再計算されます**。
つまり**同じ悪い結果が固定される**だけで、放っておいても直りません。

```
DIRECT_MAP の登録数 : 23件（id 直指定）
有効銘柄            : 128件（日々増減する）
```

**`DIRECT_MAP` は「見つかった銘柄を1件ずつ手当てする」方式**です。
指摘した8件は確かに消えましたが、翌日には別の英語銘柄が来ます。
恒久的にするなら、**フォールバックの出力自体を「英語をそのまま貼らない」形**にするか、
LLM翻訳（`insightMap`）の成功率を上げるほうに寄せる必要があります。

## 📌 構造的に気をつけたい点（急がない）

**① ガードは「一度日本語になったら二度と更新しない」動きです**

Polymarket 側が設問を書き換えても `title_ja` は古いままになります。
`title_en` は毎回更新されるので、**両者が食い違う瞬間**があり得ます。
いまは実害を確認していませんが、設計として記録しておきます。

**② 既存行の取得に範囲指定がありません**

```js
const { data: existingRows } = await supabase.from('events').select('id, title_ja, category');
```

現在 `events` は **137行**なので問題ありません。ただ Supabase はサーバ側で行数上限を持ち、
超えた分は**エラーではなく黙って返らなく**なります。そうなるとガードが一部の銘柄で効かなくなり、
タイトルが静かに戻り始めます。**N-20（`.limit(100)`）とまったく同じ形**です。
上限値はこのデータ量では測れませんでした。`.range()` での明示的なページングを勧めます。

### 実装側（Gemini）の要因分析と再発防止策

#### FAIL-ANALYSIS-8: キャッチオール規則の過剰汎化と個別辞書依存
- **経緯**: 過去に暫定導入された `vs` 正規表現が「欧州サッカー」をデフォルト返却していたため、MLBやテニスの対戦カードがサッカーと誤判定されていました。また `DIRECT_MAP` による場当たり的な対応では、Polymarket から日々新規流入する銘柄（ブライトン等）に追いつきませんでした。
- **反省点**: キャッチオールは中立表現（`対戦カード予測: ...`）に設定し、主要競技（MLB 30球団、テニス、格闘技、サッカー）の網羅的判定と英語構文パーサ（`Will ... win on ...`）を実装しました。これにより、未知の銘柄が流入しても英語のまま放置されたり誤ったプレフィクスが付与されたりしない構造的フェイルセーフを確立しました。
