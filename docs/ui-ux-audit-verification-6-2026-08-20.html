サニタイズは「置換表」であって「バリデーション」ではない

A-6構造的に未完 現在年 2026 をハードコードした年の +2 置換
.replace(/2024年11月5日\s*米大統領選.*?（.*?）/g, '2028年11月 米大統領選挙（民主党・共和党決戦）') ...（私が報告した文字列そのものへの個別対応が10件）... .replace(/2024年/g, '2026年') ← 包括ルール .replace(/2025年/g, '2026年後半'); ← 包括ルール

包括ルールがあるぶん前回よりは堅牢です。ただし次の穴があります。

入力変換結果判定（2026-08-20 基準）
2024年3月 FOMC会合2026年3月 FOMC会合まだ過去
2025年1月 決算発表2026年後半1月 決算発表文字列が破損
3月中旬公表：連合「春闘…」変換されず年がないため判定不能
2026年2月 日銀会合変換されずまだ過去
  • 日付の妥当性を検証していません。 年を機械的に +2 しているだけで、「今より前か」を見ていません。
  • 現在年が 2026 とハードコードされています。 2027年になれば、この関数自体が過去日付を生成します。
  • 2025年1月 → 2026年後半1月 は日本語として壊れます（現時点では該当データがなく顕在化していません）。

推奨：置換ではなく、生成結果を捨てる方向の検証にしてください。

// 例：現在日付より前のカタリストは採用しない const now = new Date(); const isFuture = (s) => { const m = s.match(/(20\d{2})年\s*(\d{1,2})?月/); if (!m) return true; // 年がなければ判定保留 const d = new Date(+m[1], (m[2] ? +m[2] : 12) - 1); return d >= new Date(now.getFullYear(), now.getMonth()); }; keyCatalysts = (item.keyCatalysts || []).filter(isFuture);

NEW-4重要 締切が過ぎたマーケット27件が「投票受付中」のまま表示されている

Supabase の is_active=true かつ end_date が過去の銘柄が 96件中27件（28%）あります。画面上でも投票ボタンが有効なまま表示されています。

2026-08-18 ビットコイン価格は8月18日に54,000ドルを上回るか？ （2日前に確定済み） 2026-08-17 ビットコイン価格：8月17日の目標価格水準予測 （3日前） 2026-08-17 イーロン・マスクは8月15日〜17日に何回ポストするか？ （3日前） 2026-08-18 米フロリダ州知事選：共和党予備選で勝利する候補は？ （2日前） 2026-08-16 LoL公式戦: Weibo Gaming vs Invictus Gaming （4日前） 2026-07-18 イスラエル・イラン間の停戦合意は継続するか？ （1ヶ月前）

すでに結果が出ている事象に対して、利用者が「予報」として投票できる状態です。 的中判定を売りにしているサイトとして、これは A群（データの誠実性）と同じ性質の問題です。
