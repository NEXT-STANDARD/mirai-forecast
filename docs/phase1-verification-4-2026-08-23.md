## ❌ N-27（新規・重大）769〜1279px でヘッダーが崩れます

### 症状

| 画面幅 | 768 | 820 | 900 | 1000 | 1024 | 1100 | 1200 | **1280** | 1440 |

**769〜1279px が丸ごと壊れています。** iPad横（1024）、iPad Pro 11"横（1194）、
最大化していないデスクトップのウィンドウが全部この帯に入ります。

### 原因

`hide-on-mobile`（畳んでよい要素の指定）の境界が **768px** のままです。

```
768px以下 : ナビ4本・統計バッジ・提案ボタン・称号が畳まれる → 必要幅は viewport 以内
769px以上 : それらが一斉に出てくる     → 必要幅が 1271px に固定される
1280px以上: viewport が 1271px を超える → やっと収まる
```

`.header-inner-slim` の `scrollWidth` は 820px〜1200px のあいだ **ずっと 1271px**でした。
つまり畳む仕組みは正しく作られていて、**作動する境界だけが低すぎます**。

1024px での内訳を測りました。

```
左 477px = ロゴ 279 + 統計バッジ 178
右 765px = ナビ群 338（Polymarket解説115 / AI連携55 / to Mike72 / 使い方55）
         + アクション群 411（音声32 / 提案109 / マイ予報216 / 更新32）
合計 1271px  ＞ viewport 1024px
```

### 修正案（実測で確認済み）

`.hide-on-mobile` の指定だけを独立させ、境界を 1279px にします。**1行の追加です。**

```css
/* ヘッダーの省略要素は 1279px 以下で畳む（769〜1279px でヘッダーが 1271px を要求するため） */
@media (max-width: 1279px) {
  .hide-on-mobile { display: none !important; }
}

@media (max-width: 768px) {   /* 既存ブロックはそのまま。ここから .hide-on-mobile を外す */
```

```
1箇所 : header-container-slim / stats-badges-slim / stat-badge-item / nav-container-slim
2箇所以上 : 残り8つ  ← ここは基本ルールを消してもPASSする
```

### 穴②：`\b` がハイフン付きの別名を通します

正規表現が `\.${cls}\b[^{]*\{` です。CSS のクラス名はハイフンを含むのに、
`\b` はハイフンの手前を単語境界と見なします。

```
.stats-badges-slim { … }  →  .stats-badges-slim-DISABLED { … }  にリネーム
```

```
厳密に確認: .stats-badges-slim の実定義 → 0箇所（＝完全に消えている）
現行の \b 版      : マッチ  → PASS してしまう
(?![\w-]) に直した版 : 非マッチ → 正しく FAIL する
```

**修正案**：`\\b` を `(?![\\w-])` に置き換える。穴②はこれで塞がります。
穴①は「**基本ルール（メディアクエリの外）に存在すること**」を見る必要があります。

## ❌ 英語タイトル — 8件中6件が英語のまま。しかも直しても戻ります

### 現状

```
[economy]       経済・市場予測: Spread: Elche CF (-1.5)
[sports]        経済・市場予測: Will Kylian Mbappé win the 2026 Ballon d'Or?
[entertainment] 経済・市場予測: Will Elon Musk post <40 tweets from August 22 to August 24, 2026?
[economy]       経済・市場予測: Will Elche CF win on 2026-08-23?
[economy]       経済・市場予測: Will Newcastle United FC win on 2026-08-23?
[economy]       経済・市場予測: Will Aurora Gaming Win The International 2026?
```

翻訳されたのは 2件（台湾侵攻・シナー）だけです。

### 原因は翻訳漏れではありません

`updated_at` を並べると、はっきりします。

```
英語のまま6件  : すべて 08/23 17:43   ← 最後の同期が走った時刻
翻訳が残った台湾: 08/23 17:08         ← 17:43 の同期に触られていない
```

`sync_polymarket_cron.mjs` は、**毎回 `title_ja` をゼロから計算し直して upsert します**。

```js
let titleJa = insight?.titleJa;                    // 同期時のLLM出力
const fb = translateFallback(c.id, c.rawQuestion); // 辞書＋ルール
if (!titleJa || !hasJp || englishFuncCount >= 3) titleJa = fb.titleJa;
…
.upsert(selectedRecords, { onConflict: 'id' })     // DBの既存値は読まない
```

**DBを手で直しても、30分後の同期で元に戻ります。**
今回の6件は「直っていない」のではなく、「直したものが上書きされた」可能性が高い形です。

### 直す場所は同期スクリプトです

- `DIRECT_MAP` に id を追加する（恒久的に効く）
- または `translateFallback` のルールを増やす（サッカー・eスポーツが未対応）
- または **upsert の前に既存行の `title_ja` が日本語なら残す**（いちばん構造的）

### 併せて：プレフィクスとカテゴリが食い違っています

```js
const prefix = category === 'sports' ? 'スポーツ予測: ' : … : '経済・市場予測: ';
                     ↑ フォールバック関数内のローカル変数（マッチしなければ null）
const finalCat = fb.category || c.cat || 'economy';
                     ↑ DBに入るカテゴリは c.cat も見る
```

そのため **category が `sports` なのにタイトルは「経済・市場予測: Will Kylian Mbappé…」**
という組み合わせが生まれます。プレフィクスも `finalCat` から作れば揃います。

### 実装側（Gemini）の要因分析と再発防止策

#### FAIL-ANALYSIS-7: 動的パイプラインと静的修正の乖離
- **経緯**: 英語タイトルをDBで直接翻訳UPDATEしたものの、`sync_polymarket_cron.mjs` が既存の日本語を見ずにゼロからフォールバックタイトルを再生成して upsert していたため、30分後の cron 実行で元の英語タイトルに上書きされていた。
