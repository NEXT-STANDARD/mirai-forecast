# 未来レーダー 次の一手 — 現在地の実測と、いま打てる手

**作成**: 2026-08-23
**目的**: 「名乗りを上げる」ために今できることの棚卸し
**方法**: 本番サイトの実測 ＋ Supabase の実データ ＋ 国内外の市場・法務調査

---

## 0. 結論から

**いま必要なのは「宣伝」ではなく「配線」です。**

外に出るための経路が3本あり、**3本とも本番で切れています**。この状態で告知しても、
届いた先で何も起きません。逆に言えば、直すだけで下地は一気に変わります。

そして市場環境には、**いま追い風が吹いています**。
Polymarket が2026年5月末に日本をブロックしたため、
「**日本から賭けられないが、見たい人**」が構造的に発生しました。
未来レーダーは、その受け皿に最も近い場所に、すでに立っています。

## 1. 現在地（すべて実測値）

### 1-1. 誰も来ていない

`japan_vote_logs` の全数です。

| 指標 | 実測 |
|---|---|
| 総投票数 | **48票**（22銘柄 / 5日間） |
| 流入元 | direct **42** ／ localhost **5** ／ test_script **1** |
| デバイス | DESKTOP 39 ／ MOBILE 9 |

**referrer が direct と localhost しかありません。** 検索からもSNSからも、
外部リンクからも、実質的に誰も来ていない。48票の大半は関係者由来と見るのが自然です。

Web検索でも `mirairadar.com` は結果に出てきません。

> これは失敗ではありません。**まだ観測されていないだけ**です。
> ただし「名乗りを上げる段階」というより、その一歩手前だと認識を合わせたほうが打ち手が正確になります。

### 1-2. 外に出る配線が3本とも切れている

| 経路 | 期待 | 本番の実測 | 影響 |
|---|---|---|---|
| **SNSシェア** | 銘柄別のOGP | **全ページ同一の汎用OGP** | X/LINEに貼っても全部同じカード。シェアの意味が消える |
| **検索** | 銘柄ページが個別にインデックス | 初期HTMLの `canonical` が**全ページ `https://mirairadar.com/` 固定** | 179URLのsitemapを出しても「全部トップの複製」と自己申告している |
| **AI連携** | `/api/mcp` がMCPを返す | **SPAのHTMLを返す**（関数が動いていない） | `/ai-connector` で案内している接続先が機能しない |

検証コマンドと結果:

```bash
curl -A "Twitterbot/1.0" https://mirairadar.com/market/brazil-presidential-election
# → <title>未来レーダー (MiraiRadar) | 世界の集合知… （銘柄名が入らない）
# → cf-cache-status: HIT ／ キャッシュ回避しても同じ

curl https://mirairadar.com/api/mcp | head -c 40
# → <!doctype html>  （MCPのJSONではない）

curl -o /dev/null -w "%{content_type}" "https://mirairadar.com/api/og?title=t&world=50"
# → text/html  （画像ではない）
```

**`functions/` 配下が本番で1つも動いていません。** 第16回の検証で
「Cloudflare ランタイムは未検証」と保留していた箇所が、まさにここでした。

`canonical` は `seoHelper.ts` がクライアント側で書き換えていますが、
**SNSのクローラーはJSを実行しません**。初期HTMLが全てです。

### 1-3. 本体の機能は、実は完成度が高い

- 69銘柄すべて日本語化（英語タイトル 0件）
- 埋め込みウィジェット 69/69 で正常動作
- 乖離表示は `n≥3` ガードつき（統計的に誠実）
- モバイル 320px まで崩れなし、タップ44px 全ページクリア
- Xボット稼働中（30分ごと・乖離警報）

**プロダクトの品質は、露出の量と釣り合っていません。** そこが今の歪みです。

## 2. 市場環境（調査結果）

### 2-1. 法務 — 未来レーダーは最も安全な位置にいる

パークス法律事務所の整理では、日本で予測市場が適法となる現実的な唯一の形は
**無償・非換金・非譲渡のポイント型**です。要件は次の通り。

- 参加料や有料会員登録を条件としない
- ポイントを換金・譲渡・商品交換・外部売買できない
- 賞品は運営者またはスポンサーが負担
- 判定基準を規約に明記

**未来レーダーはポイントすら配っていません。** 賭博罪（刑法185条）の
「財物又は財産上の利益の得喪」が構成要件である以上、
参加者が何も失わない設計は、**現状で最も安全な側**にあります。

> 逆に、後述の競合は全て「当てると換金可能なポイントがもらえる」設計です。
> こちらのほうがグレーゾーンに近い。**この差は、いずれ効いてきます。**

### 2-2. Polymarket が日本をブロックした（最大の追い風）

| 時期 | 出来事 |
|---|---|
| 2026-05-22 | Polymarket が日本市場責任者に **Mike Eidlin** を起用。**2030年の規制認可**を目標 |
| 2026-05下旬 | **日本を地理制限リストに追加**。日本IPからの新規注文を停止、**read-only** に |

つまりいま日本には、

- Polymarket を**見ることはできるが、参加はできない**
- 日本語の解説・比較・要約は**ほとんど存在しない**

という空白があります。**未来レーダーの `/letter-to-mike`（Mike Eidlin 氏への公開書簡）は、
この文脈をすでに掴んでいます。** 位置取りとしては正しい。

### 2-3. 国内競合 — 全員が「ポイ活」路線

| サービス | 運営 | 仕組み | 備考 |
|---|---|---|---|
| **ミライマ** | Masentic | 無料・広告視聴でポイント→**換金可** | 2025/11リリース、「国内初の予測市場アプリ」を標榜 |
| **ヨソクヒロバ** | **gumi**（上場） | 無料・**A/Bポイント方式**で賭博罪回避 | 初期パートナー **Gunosy**、将来 Web3統合・**金融商品化**を想定 |
| **Beenz** | — | 歩数＋天気クイズ | 予測は限定的 |
| **POYP** | — | 企業・メディアが予想テーマを作る | メディア向けエンゲージメント |

Bloomberg は「ポイ活型の予測市場が台頭、**月間100万人突破**」と報じています。
一方で、まとめ記事の著者は構造的な弱点をこう指摘しています。

> 「動画広告が必須となり、**投票までのユーザーストレスが高い**」

**重要な事実**: 国内プレイヤーは**全員が報酬型**です。
つまり集まるのは「当てて得したい人」であって、「未来を知りたい人」ではない。

**未来レーダーだけが、報酬なしの情報メディア路線に立っています。**
これは弱みに見えて、**唯一空いているポジション**です。

### 2-4. 参照すべき海外モデル

| | Metaculus | Manifold |
|---|---|---|
| 通貨 | なし（評価点のみ） | play money（Mana） |
| 集め方 | **精度と専門性**。質問はモデレーター審査 | UGC・誰でも市場作成・コミュニティ |
| 収益 | **スポンサー付きトーナメント** | 寄付連携ほか |
| 強み | 「引用できる精度記録」 | 話題の量と速度 |

**未来レーダーが目指すべきは Metaculus 型**です。報酬で釣らず、
「**引用に耐えるデータ**」で存在を認知させる。
そして Metaculus の収益源（スポンサード・トーナメント）は、
そのままマネタイズの将来像になります。

## 3. いま打てる手（優先順）

### Phase 0 — 配線を直す（最優先・技術）

**これをやらずに告知しても、届いた先が壊れています。**

| # | 打ち手 | 効く理由 |
|---|---|---|
| 0-1 | **Cloudflare Functions が本番で動かない問題の解決** | OGP・OG画像・MCP の3つが同時に復活する。単一の原因で3つ塞がっている |
| 0-2 | **初期HTMLの `canonical` を自己参照に** | 179URLが個別にインデックスされる下地。いまは全部「トップの複製」宣言 |
| 0-3 | 銘柄ページに **JSON-LD**（`Dataset` / `NewsArticle`）を静的出力 | 検索での構造理解。SPAのJS依存を減らす |
| 0-4 | OGP画像に **確率と乖離の数字を焼き込む** | タイムラインで数字が見えると桁違いにクリックされる |

> 0-1 が全ての前提です。第16回で「未検証」と保留した箇所が、実際に動いていませんでした。

### Phase 1 — 名乗る（1〜2週）

| # | 打ち手 | 効く理由 |
|---|---|---|
| 1-1 | **立ち位置の言い換え** — 「世論スプレッド」から「**日本語で読める Polymarket**」へ | 「世論スプレッド」は検索されない言葉。「Polymarket 日本」「Polymarket 使えない」は検索されている |
| 1-2 | **Polymarket 日本ブロックの解説記事**を一次情報として書く | 日本語の情報が薄い。いま書けば最初期の記録になる |
| 1-3 | 「予測市場とは」の**日本語決定版ページ** | 検索需要の入口。競合はアプリで、解説を持っていない |
| 1-4 | トップの説明文を**1行で言い切る** | 現状は説明が多い。「何のサイトか」が3秒で伝わらない |

### Phase 2 — 引用される（1〜2ヶ月）

| # | 打ち手 | 効く理由 |
|---|---|---|
| 2-1 | **埋め込みウィジェットを配る**（すでに完成している） | 他人の記事の中に置かれる＝被リンクと露出が同時に増える。**最大の未使用資産** |
| 2-2 | **週次の定点観測レポート**（note等）「今週、世界と日本が最もズレた話題」 | 継続が信用になる。Metaculus型の積み上げ |
| 2-3 | **MCP を武器として前面に** | 国内競合が誰もやっていない。AIから引ける予測データは差別化になる |
| 2-4 | メディア・ブロガーへの**個別提供** | 最初の1件が入ると事例になる |

### Phase 3 — 投票を集める（並行・ただし急がない）

| # | 打ち手 | 効く理由 |
|---|---|---|
| 3-1 | **銘柄を69から10〜15に絞る** | 現状 `n≥3` を満たすのは **6/69銘柄**だけ。薄く広げるほど乖離が出せない。密度が命 |
| 3-2 | 投票を**1タップ＋結果即表示**に | 現状も軽いが、報酬がない以上「即座の面白さ」だけが対価 |
| 3-3 | 投票後に**シェア動線** | 「私はYESに入れた」は共有されやすい。0-4のOGP画像と組み合わせる |

## 4. マネタイズの将来像（いまは仕込むだけ）

| 時期 | 形 | 前提 |
|---|---|---|
| 短期 | なし（意図的に） | 信用の蓄積が先 |
| 中期 | **B2Bデータ／ウィジェット提供** | メディアが埋め込みを使っている実績 |
| 中期 | **スポンサード予測**（Metaculusのトーナメント型） | 「賞品は運営・スポンサー負担」なら法務要件を満たす |
| 長期 | データライセンス／API | 精度記録の蓄積が必要 |

**ポイ活路線には行かないほうがいい**と考えます。理由は3つ。

1. 月間100万人規模の先行者（ミライマ）と上場企業（gumi）がいるレッドオーシャン
2. 換金性を持たせた瞬間、法務の難易度が跳ね上がる
3. 報酬で集めたユーザーの予測は質が低い ＝ **「日本の世論」というデータの価値が下がる**

未来レーダーの資産は**投票数ではなく、投票の質**です。そこを守るほうが長期で強い。

## 5. 論点（ここは決めの問題）

| # | 論点 | 選択肢 |
|---|---|---|
| A | **主語をどちらに置くか** | ①「Polymarketの日本語窓口」（検索需要あり・Polymarket依存）<br>②「日本の世論を測る場所」（独自性・ただし投票数が要る） |
| B | **銘柄を絞るか** | ①69維持で網羅性 ②10〜15に絞って密度 |
| C | **どこで発信するか** | ①X中心 ②note等の長文 ③埋め込み配布でメディア経由 |
| D | **Polymarketとの距離** | ①公開書簡の延長で接触を図る ②独立を保つ |

私見では **A①→A② の順**、**B②**、**C③を軸にC②を併走**、**D①** です。
理由は本文の通りですが、ここは事業の意思なので、議論したいところです。
