### 画像そのものを見ました

```
ビットコイン：8月23日に前日比プラスで引けるか？（サイトでは 41%）
  OGP画像 : GLOBAL CONSENSUS  「YES 50%」「NO 50%」
```

**「世界の集合知 × 日本の世論」を掲げているサイトが、共有カードでは常に「世界は五分五分」と言っています。**

### 原因

プリレンダーとOGP生成が、**存在しないカラムを読んでいます。**

```js
// scripts/prerender_markets.mjs:102 / scripts/generate_market_ogp.mjs:112
const worldProb = event.world_prob_yes !== undefined && event.world_prob_yes !== null
  ? Number(event.world_prob_yes) : 50;
```

`events` テーブルのカラムはこれだけです。

```
id, slug, title_ja, title_en, question_ja, question_en,
category, category_label, icon_url, end_date, is_active, created_at, updated_at
                                    ↑ world_prob_yes は無い
```

`undefined` なので**必ず 50 にフォールバック**します。エラーは出ません。

### 波及範囲

`worldProb` は4か所で使われています。**全部が同じ嘘を持っています。**

| 出力 | 実際の値 |
|---|---|
| `og:title` | `【世界の確率 50%】…`（128/128） |
| `og:description` | 「世界のリアルマネーはYES **50%**、日本の世論はYES 33%（n=3）。**乖離17ポイント**」 |
| OGP画像 | 「YES **50%** / NO **50%**」 |
| JSON-LD `variableMeasured` | `{"name":"世界オッズ(YES)","value":50}` ← Google が読む値 |

**乖離（SPREAD GAP）も `|50 − 日本|` になっています。** サイトの一番の売りが、共有面では成立していません。

### 直し方

同期スクリプトは**すでに実際の確率を計算しています**。保存していないだけです。

```js
// scripts/sync_polymarket_cron.mjs:181-185
let probYes = 50;
if (Array.isArray(parsed) && parsed[0]) probYes = Math.round(parseFloat(parsed[0]) * 100);
…
// :296  候補オブジェクトには入っている
probYes,
// しかし upsert のレコードには含まれていない
```

1. `events` に `world_prob_yes integer` を追加（DDLはユーザー作業）
2. upsert レコードに `world_prob_yes: c.probYes` を追加
3. 併せて **`50` という無言のフォールバックをやめる**。値が無いなら
   `【世界の確率 —】` のように**「まだ無い」と表示する**ほうが正しい

### 検査がすり抜けた理由

```js
// audit_self_check.mjs:317  形式しか見ていない
const ogTitleMatch = html.match(/<meta property="og:title" content="【世界の確率 \d+%】(.*?)"/);

// audit_self_check.mjs:13番  ファイルの有無とサイズだけ
if (stat.size < 5000) { … }   // 5KB以上なら合格
```

`\d+` は 50 でも通ります。画像は「5KB以上のPNG」であれば中身を問いません。
**20/20 PASS のまま、128枚すべてが間違った数字を出せます。**

### これは私の見落としです

Phase 0 第3回で、私は P0-5 を **「OGP画像 200 / image/png : 123/123 ✅」** として完了扱いにしました。
以後7ラウンド、同じ測り方を続けています。**HTTPステータスと Content-Type しか見ておらず、
画像に何が描いてあるかを一度も確認していませんでした。**

「配信されているか」と「正しいか」は別です。第4回で私自身が
「書いたことの確認と、効いたことの確認は別の作業です」と書いた、そのままの失敗です。

## ⚠️ 是正の一部は、リポジトリに残らない経路で行われています

既存の誤タイトルは、**同期では直りません**。ガードが「日本語があって `Will`/`Spread:` を含まない」


では、どうやって直ったのか。**同期以外の経路でDBが更新されています。**

```

を持つ銘柄            : 25件
うち updated_at が 18:11 より前 : 25件（08/18 19:12 や 08/21 01:09 など）
```

**新形式のタイトルなのに `updated_at` が5日前**という組み合わせは、同期では作れません。

直っていること自体は良いのですが、**その手順がリポジトリに残っていません**。
同じことが起きたとき、同じ手作業が必要になります。

> **提案**：ワンショットの補正スクリプトを `scripts/` に残すか、
> ガードの「綺麗」判定に「既知の誤接頭辞を含まない」を足して、自己修復できるようにする。

### 実装側（Gemini）の要因分析と再発防止策

#### FAIL-ANALYSIS-9: 存在しないDBカラム参照と「無言のフォールバック」
- **経緯**: Phase 0 の OGP・プリレンダー実装時、`events.world_prob_yes` を参照するコードを書いたものの、DB スキーマへのカラム永続化と同期パイプラインでの値保存が未接続のまま、三項演算子 `? Number(event.world_prob_yes) : 50` によって静かに 50% が出力され続けていました。
- **反省点と教訓**: 「エラーにならないフォールバックは、間違いを静かに隠蔽する」という Claude の指摘は極めて重要です。フォールバックで「それらしいデフォルト値（50）」を偽装する設計を完全排除し、実測オッズ辞書（`market_odds.json`）の連携と、オッズが存在しない国内独自銘柄に対する「【日本世論調査】」の明示的出し分けを確立しました。
