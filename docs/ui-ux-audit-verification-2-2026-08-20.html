NEW-1実害あり PWA バナーが利用規約・プライバシーポリシーのリンクを覆い、クリックを奪う

モバイルでページ最下部までスクロールすると、PWA バナー（z-index: 1000 / 343×217px）が 新設したフッターリンクの真上に重なります。

利用規約 重なり 39×26px 中心が奪われている: true プライバシーポリシー 重なり 120×26px 中心が奪われている: true

document.elementFromPoint でリンク中心を叩くと PWA バナーが返る ＝タップしてもリンクは反応しません。

PWA バナーは「スクロール 400px 超」で表示される仕様のため、 フッターに到達した時点で必ず表示されており、必ず重なります。 G-2（規約リンクの新設）の効果を、PWA バナーのスマート化が打ち消している形です。

対策：バナー表示中はフッターに下部余白を足す、またはフッター到達時にバナーを自動的に隠す。

NEW-2開発体験 dev サーバーでは spacing ユーティリティが効かない（本番のみ正常）

同一コードで、vite build の出力と vite dev の出力が異なります。

* {…} の所属pb-16p-3text-world
本番ビルド（4173）@layer base64px12pxrgb(56,189,248)
dev サーバー（5173）★レイヤー外★0px0px継承色

dev 側はサーバー再起動＋node_modules/.vite 削除後、新規タブでも再現します。 src/index.css のソースは @layer base { * {…} } と正しく書かれており、 /src/index.css が返す CSS 文字列でもレイヤー内にあるため、 Vite の dev 用 CSS 注入経路のどこかで @layer が失われていると考えられます。

実害：利用者に届く成果物は正常なので本番影響はありません。 ただし開発者はローカルで余白が崩れた画面を見ることになり、 「まだ直っていない」と誤認して不要な修正を入れるリスクがあります。 第1回検証で私自身が踏んだ落とし穴でもあります。

対策：判定は必ず vite build → vite preview で行う。

NEW-3軽微 pb-16（64px）より固定バー（81px）のほうが高い

差分 17px。実機では隠れるテキスト要素は 0 件で実害は出ていませんが、余白がバー高より小さい構造は残っています。 バー高は D-4 の銘柄名追加で 71 → 78 → 81px と伸び続けているため、 pb-24（96px）か calc(81px + env(safe-area-inset-bottom)) のような明示指定が安全です。
