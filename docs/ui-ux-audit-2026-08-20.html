総評

このプロダクトの弱点は「デザインの好みが悪い」ことではありません。 2 つの構造的な問題が、良い部分をすべて打ち消しています。

1 つめは、情報密度という前提が日本語で成立していないこと。 「Cyber-Bloomberg Terminal」というコンセプト自体は明確で、方向性としては筋が通っています。 ただしブルームバーグ端末が成立するのは、大型モニタで英数字を扱うからです。 同じ密度を漢字かな交じり文で再現しようとした結果、画面上のテキストの 86% が 12px 未満、 最頻値は 9.9px になりました。9.9px の漢字は、多くの利用者にとって「読みにくい」ではなく「読めない」水準です。 皮肉なことに、このサイトで最も読みやすいのは一番下のコンプライアンス免責文でした。

2 つめは、信頼性を売り物にしながら、表示データの一部が実在しないこと。 「実測」「REAL DATA ONLY」「リアルタイム解析済み」というラベルが各所に置かれている一方で、 全国ランキングは架空の 7 人、X シェアカードの「日本の世論」は常に 50% 固定、 乖離ランキングの 1 位は 1 票から算出されています。 これは UI の問題であると同時に、ブランドの問題です。1 人でも気づけば、 サイト全体の数字が疑われます。

逆に言えば、直すべき順番ははっきりしています。 捏造データを止める → スタイル基盤を直す → 文字を読める大きさにする。 この 3 つを終えるまで、新機能を足す意味はほとんどありません。

A

データの誠実性

最優先。UI の見た目ではなく、UI が主張している内容の問題です。

A-1P0 「全国クォンツ・リーダーボード」が完全な架空データ。しかも未投票ユーザーの的中率が 75% と表示され、そのまま X にシェアできる

ForecastHubPage.tsx:73 の leaderboardData は 7 人分のハードコード配列です。 画面の説明文は「全国のトップアナリスト・予報士たちの的中率と活動ランキングです」と、実在の利用者として提示しています。 アカウント機能が存在しない以上、全国ランキングは原理的に成立しません。

さらに深刻なのが accuracy: accuracyRate ?? 75 です。 投票数 0 の新規ユーザーにも「的中率 75%」が表示され、同じ画面の「自慢シェア」ボタンから その数字を添えて X に投稿できます。捏造した実績を利用者本人に発信させる導線になっています。

{ rank: 4, name: 'あなた (You)', accuracy: accuracyRate ?? 75, ... } → 投票 0 件でも「的中率 75%」。X シェア文面にそのまま埋め込まれる
A-2P0 X シェアカードの「日本の世論」が常に 50% 固定。拡散されるカードすべてが実データではない

functions/market/[slug].ts はクローラー向け OGP を生成しますが、 japanProb は 50 の初期値のまま一度も更新されません。 結果、OGP と Twitter Card の説明文は必ず 「🇯🇵 日本の世論：YES 50%（ギャップ |world-50|%）」になります。

本サイトの成長ループはシェアです。そのループが毎回、実在しない世論値を配信しています。 A-1 が「サイト内で見つかると痛い」問題なら、これは「サイト外に出て行く」問題です。

A-3P0 看板機能「乖離ランキング」が n=1 と 0 票で成立している

SpreadRankingSection.tsx:39: const japanYes = ev.japanVotes.total > 0 ? ev.japanVotes.percentYes : 50;

実測画面での 1 位は「パリ・サンジェルマンが CL 制覇するか？ / 86% 乖離」でした。 世界オッズ 14%、日本側は YES 1 票のみ（＝100%）。差の 86% が 「世界のスマートマネーとお茶の間の直感が最も激突しているテーマ」として最上位に出ています。

0 票の銘柄も「日本は 50%」と仮定して順位に入るため、 誰も投票していない銘柄が「世論が激突している」と表示され得ます。 個別ページには「（1票）」と正直に併記されているのに、ランキングカードには件数がありません。同じ数字の扱いが画面間で不一致です。

A-4P0 「Gemini 3.7 Flash リアルタイム解析済み」の実体はキーワード分岐の固定文。API 呼び出しコードはデッドコード

polymarketService.ts の resolveAiInsight() は、 タイトルに「大谷」「日銀」「ビットコイン」等が含まれるかを if で判定し、 あらかじめ書かれた文章を返す関数です。lastUpdated には 文字列 'Gemini 3.7 Flash リアルタイム解析済み' がハードコードされています。

実際に Gemini を呼ぶ geminiService.ts は src 内から一度も import されていません（呼び出し 0 件）。 UI 側は「LIVE ANALYTICS」バッジ付きで表示し、フッターは「Powered by … Gemini 3.7 Flash」と署名しています。

事前生成した分析を使うこと自体は妥当です。問題は静的なテーブルに「リアルタイム」と書いていることです。

A-5P1 チャートの始値・高値・安値は合成値。それを「● Polymarket 実測同期済み」と表示している

MainTradingChart.tsx の OHLC は open: prob-1 / high: prob+2 / low: prob-2 で機械的に作られています。 出来高バーも 24h 累計値に係数を掛けた飾りです。株価チャートの体裁を借りているため、 利用者は本物の四本値だと解釈します。

A-6P1 「次回注目カタリスト」に過去日付が並んでいる

aiInsightsMaster.ts（38 銘柄）に 2024/2025 年基準の日程が 20 箇所残っています。 現在 2026-08-20 の画面に、「12月12日：The Game Awards 2024 での電撃ティザー公開有無」 「11月5日：任天堂 2025年3月期第2四半期決算」 「2月21日発表：総務省 1月全国消費者物価指数」 が「次回」として表示されます。

A-7P1 コメントが保存されない。投稿してもリロードで消える

MarketDetailPage.tsx の handleAddComment は setComments のみで、 永続化処理がどこにもありません（services 内にコメント関連コード 0 件）。 アバターは Unsplash の他人の顔写真が全員共通で固定されています。

加えて useState(item.comments || []) は初期化時にしか評価されないため、 関連銘柄へ遷移しても前の銘柄のコメントが残り続けます。

C

可読性・日本語組版

日本語サイトとして、ここが最も影響範囲の広い問題です。

C-1P0 画面上のテキストの 86% が 12px 未満。最頻値 9.9px（257 箇所）
実測フォントサイズ分布（トップページ・可視テキストノード 675 件） 9.3px ▓▓▓▓▓▓ 66 9.9px ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ 257 ← 最頻値 10.4px ▓▓▓▓▓ 54 10.9px ▓▓▓▓▓▓▓▓▓▓▓ 117 11.5px ▓▓▓▓▓▓ 69 12px 以上 ▓▓▓▓▓▓▓▓ 95 12px 未満: 580 / 675 = 86%

ラテン文字なら 10px でも判読できます。漢字は画数が多く、同じサイズでは字形が潰れます。 日本語の本文は 16px 前後、補助情報でも 13〜14px が下限というのが一般的な指針です。 9.9px は補助情報のサイズではなく、判読不能のサイズです。

これは装飾の問題ではなくコンセプトの帰結です。ブルームバーグ端末の密度を日本語で再現しようとすると、 必ずここに突き当たります。密度を捨てるか、日本語を捨てるかの二択で、前者を選ぶべきです。

C-2P1 コントラスト WCAG AA 不合格が 186 箇所（28%）。主犯は --text-muted: #64748b

ダーク背景に対して 3.4〜4.05:1。AA の基準 4.5:1 に届きません。 カテゴリタグ、日付、出来高、パーセント記号、「いいえ、一般の訪問者です」など、 低優先度として意図的に薄くした要素がまとめて落ちています。

単純に --text-muted を #8A96A8 程度まで持ち上げるだけで大半が解決します。 C-1 の文字サイズ拡大と同時に行えば、階層の見え方は保てます。

C-3P1 禁則処理の設定がゼロ。見出しが「日／本の世論」で改行される
index.css 内の出現数 word-break 0 line-break 0 overflow-wrap 0 text-wrap 0

実機（375px 幅）のオンボーディング見出しで 世界のスマートマネー vs 日 / 本の世論 と、 「日本」が分断されて改行されました。 カラム幅が狭い箇所が多いため、同様の破綻が各所で起きています。

対策は 1 箇所です。body に word-break: auto-phrase; line-break: strict; overflow-wrap: break-word;、 見出しに text-wrap: balance。この監査ページ自体に同じ設定を入れてあります。

C-4P2 画像が 1 枚もない。iconUrl は型に定義されているが未使用

実測で <img> 0 件、background-image 0 件。 MarketItem.iconUrl はどこからも参照されていません。 極小テキストと絵文字だけで 84 銘柄が並ぶため、視覚的な取っかかりがなく、走査性が著しく低い状態です。

isAdminOpen / isLetterPageOpen / isAiConnectorOpen / isForecastHubOpen / detailMarketId の 5 状態が排他であるべきなのに、 遷移関数のたびに 4 つを手で false にしています（App.tsx:127-182）。 1 つ書き忘れれば 2 ページが同時表示されます。

さらに App.tsx:34 で、すべての useState より前に if (embedSlug) return ... の早期 return があります。 現状は動作しますが Rules of Hooks 違反で、条件が動的になった瞬間に壊れます。 単一の route 状態、または react-router へ寄せるべき箇所です。

F-4P2 .gitignore の *.json が manifest.json を巻き込んでいる

.gitignore:32 の一括除外により、 public/manifest.json と public/data/ai_insights.json が git 管理外です（git check-ignore で確認済み）。 クリーンな clone からビルドすると PWA マニフェストが欠落します。

three、googleapis、sharp、twitter-api-v2、 @google-analytics/data、clsx は src から一度も import されていません （node_modules は 444MB）。スクリプト用途のものは devDependencies へ移すのが適切です。

G-1P1 Googlebot に本文ゼロのスタブを返している。自己参照の meta refresh 付き

functions/market/[slug].ts は User-Agent で分岐し、 正規表現に googlebot が含まれています。 Googlebot が受け取る HTML の <body> は次の 1 行だけです。

<meta http-equiv="refresh" content="0;url=${url.href}"> ← 自分自身へ <body> <p>リダイレクト中... <a href="...">タイトル</a></p> </body>

sitemap.xml に登録した 179 URL すべてが、検索エンジンから見て実質的に空です。 しかも遷移先が同一 URL のため、meta refresh を追うクローラーは同じスタブに戻ります。 利用者とクローラーに別内容を返す構造は、クローキングと判定されるリスクもあります。

OGP 生成は残し、ボット判定は Twitterbot 等の SNS クローラーに限定、 検索エンジンには実コンテンツを返す（プリレンダー等）方針に変えるべきです。
