## ✅ 記事の是正2点

### ① 法的断定 → 事実記述

```
前 : 「情報インテリジェンスツールとしては合法的に閲覧・参照することができます」
後 : 「情報インテリジェンスツール」としては利用制限の対象外であり、
      誰でも自由に閲覧・参照することができます
```

「合法」という自サイトの結論ではなく、**制限の対象かどうかという事実**になりました。
記事全体の姿勢（法解釈は引用に留める）と一貫します。

### ② 精度主張の緩和

```
前 : 数億ドルのリアルマネーが投じられた極めて精度の高い集合知データ
後 : 世界中で多額のリアルマネーが投じられ、高い予測精度を持つとされる集合知データ

前 : 既存の世論調査やアナリスト予想を凌駕する精度を示してきました
後 : 学術研究や市場実務において既存の世論調査を補完・先行する指標として
      注目を集めてきました
```

「凌駕する」という測定結果の主張が、「注目を集めてきた」という**受容の記述**に変わりました。

## 🆕 N-21（新規・構造）新規銘柄は、デプロイまで Phase 0 以前の状態に留まる

### 症状

回帰チェックで 124件中3件が canonical・OGP画像で外れました。**これは回帰ではありません。**

```
3件の追加時刻   : 2026-08-23 04:14:52 UTC（13:14 JST）
最後のデプロイ   : 13:03 JST
                  ↑ 追加はデプロイの11分後。まだビルドされていない
ローカルで再ビルド → 3件とも dist に生成される（＝仕組みは正常）
```

### ただし、この状態は放置できません

プリレンダーされていない銘柄が本番で何を返すか、実測しました。

| 項目 | 実測 |
|---|---|
| HTTP | 200（SPAフォールバック） |
| `<title>` | **「Polymarketの予測確率を日本語で ｜ 未来レーダー」**（トップのもの） |
| `og:title` | 同上（銘柄名が入らない） |
| **`canonical`** | **`https://mirairadar.com/`** ← Phase 0 で直した「全ページがトップの複製」状態 |
| sitemap | 未収録 |
| OGP画像URL | **HTTP 200 / `text/html` / 5375 bytes** ← 画像ではなくHTMLが返る |

**Phase 0 で解いた問題が、新規銘柄にだけ再発している**形です。
しかも新しい銘柄ほど話題性があり、検索・共有される可能性が高い。

### 銘柄は日次で増え続けます

本セッション中だけでも **123 → 124 → 126 → 127 → 124件**と変動していました
（生成と期限切れが同時に走っています）。デプロイがコード変更のときだけなら、
**次に誰かが push するまで新規銘柄はプリレンダーされません**。

### 推奨

**Cloudflare Pages の Deploy Hook を、既存の cron から叩く。**

`auto-bot.yml` は30分ごとに動いています。銘柄同期の直後に Deploy Hook を1回叩けば、
プリレンダーが銘柄の増減に追随します。

```yaml
- name: Trigger Cloudflare Pages rebuild
  run: curl -X POST "${{ secrets.CF_PAGES_DEPLOY_HOOK }}"
```

30分ごとのビルドが重いなら、日次生成の直後だけでも効果があります。

**併せて**：`/ogp/market/*.png` が存在しないときに **HTML を200で返す**のは、
OGPカードの画像取得を壊します。SPAフォールバックの対象から
`/ogp/` 配下を外して404を返すほうが正しい挙動です。

## 所感

**P1-3 の直し方が良かったです。**

私が指摘したのは「記事から3件」でしたが、実際に直したのは**サイト全体**でした。
トップの28枚のカード、ヘッダーのナビ、ランキング、記事——全部です。
指摘の範囲ではなく、**指摘の理由**（クローラが辿れる構造が必要）に応えています。

しかも `preventDefault` で SPA の速度を保っている。
「SEOのために体験を犠牲にする」という安易な方向に行かなかったのは、正しい判断です。

記事の是正も的確でした。「凌駕する」→「注目を集めてきた」は、
単に言葉を弱めたのではなく、**主張の種類を変えて**います。
測定結果の主張から、受容の記述へ。これは出典の要らない書き方です。

残る N-21 は、Phase 0・Phase 1 が完成したからこそ見えた問題です。
**静的な最適化と、動的に増えるデータの間には、必ず時間差が生まれる。**
その差をどう埋めるかは、プリレンダーを選んだ時点でセットで決めておくべきでした。
これは私のロードマップの設計漏れです。Phase 0 で「ビルド時プリレンダーにする」と決めたとき、
「ではビルドはいつ走るのか」まで書くべきでした。
