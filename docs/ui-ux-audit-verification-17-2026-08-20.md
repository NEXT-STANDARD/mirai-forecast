## ❌ 新チェック #9.5 は、破壊テストを通らない

エンジンに「埋め込みウィジェット スラッグ厳密照合 (N-18)」が追加され、11項目になりました。
**しかし、この判定は機能していません。**

### 破壊テスト

`EmbedWidgetPage.tsx` に N-18 のバグ（正規化）をそのまま戻して、エンジンを走らせました。

```
戻した内容：
  (e) => e.slug === slugOrId || e.id === slugOrId
       || e.slug.replace(/-\d+$/, '') === slugOrId.replace(/-\d+$/, '')

エンジンの判定：
  ✅ [PASS] 埋め込みウィジェット スラッグ厳密照合 (N-18)
     └─ 完全一致照合 (slug === slugOrId || id === slugOrId) を確認
```

**回帰を見逃したうえ、確認していないことを「確認した」と報告しています。**
第14回の #9、第15回の #3 と、まったく同じ形です。

### 原因：正規表現のエスケープ

```js
if (/replace\(\/-\\\\d\+\$\/|replace\(\/-\d\+\$\//.test(embedCode)) { … }
```

- 第1候補 `replace\(\/-\\\\d\+\$\/` → `\\\\` は**リテラルのバックスラッシュ2個**。ソースには存在しない
- 第2候補 `replace\(\/-\d\+\$\/` → `\d` は**数字1文字**。ソースは `-` の次が `\`（バックスラッシュ）なので当たらない

必要なのは `\\d`（バックスラッシュ1個 ＋ `d`）です。単体で確かめました。

```
現行の判定式   バグ版:false / 正常版:false     ← どちらにも当たらない
修正案の判定式 バグ版:true  / 正常版:false     ← 期待どおり
```

```js
// 修正案（実測で確認済み）
if (/\.replace\(\s*\/-\\d\+\$\//.test(embedCode)) { … }
```

> **より安全な形**：禁止パターンを探す（否定）のではなく、**照合式そのものが期待どおりか**を見る（肯定）ほうが、
> 別の書き方で緩められたときにも気づけます。
> 例：`events.find(` の引数内に `replace(` が現れないことを確認する。
