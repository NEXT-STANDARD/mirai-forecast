症状

本番に「欧州サッカー:」で始まる銘柄が17件あります。そのうち13件はサッカーではありません。

欧州サッカー: Atlanta Braves vs. Milwaukee Brewers 勝敗予測 ← MLB 欧州サッカー: New York Mets vs. Chicago White Sox 勝敗予測 ← MLB 欧州サッカー: San Francisco Giants vs. Cleveland Guardians ← MLB 欧州サッカー: Los Angeles Angels vs. Texas Rangers 勝敗予測 ← MLB 欧州サッカー: Chicago Cubs vs. Seattle Mariners 勝敗予測 ← MLB 欧州サッカー: Prague 2: Norbert Gombos vs Radu Mihai Papoe ← テニス 欧州サッカー: Cancun: Sebastian Baez vs Lloyd Harris 勝敗予測 ← テニス 欧州サッカー: Sion: Lorenzo Giustino vs Benjamin Hassan 勝敗予測 ← テニス 欧州サッカー: Monterrey Open, Qualification: Maya Joint vs … ← テニス

内訳：野球9件・テニス4件。 正しく欧州サッカーなのは4件（エルチェCF×2・ニューカッスル・バロンドール）だけです。

原因

translateFallback の終盤に、"vs" を含めば何でもサッカーにするキャッチオールがあります。

if (/vs\.?|対/i.test(t) && !t.startsWith('LoL') && !t.startsWith('CS2')) { let clean = …; if (/Lynx|Valkyries/i.test(t)) return { titleJa: `WNBA公式戦: ${clean} 勝敗予測`, … }; return { titleJa: `欧州サッカー: ${clean} 勝敗予測`, category: 'sports' }; // ← ここ }

MLB用のルールはチーム名のハードコード列挙です。

/Dodgers|Rockies|Orioles|Rays|Cardinals|Reds|Tigers|Pirates|Marlins|Phillies|Yankees|Red Sox/i

この12球団に入っていない Nationals・Rangers・Mets・White Sox・Braves・Brewers・Giants・ Guardians・Athletics・Royals・Angels・Cubs・Mariners は、全部キャッチオールへ落ちます。 テニスも Cincinnati Open: と ITF M25 しか個別対応がないので同じです。

これは今回の変更で入ったものではありません。 0eeae9c の1つ前にも同じ行があります。

ただ、英語タイトルが片づいた結果、いま最も目立つ誤りになりました。

直し方の提案

キャッチオールの既定を「欧州サッカー」ではなく中立にするのが素直です。

return { titleJa: `対戦カード予測: ${clean}`, category: 'sports' };

競技を当てにいくなら、ハードコード列挙ではなくPolymarket側のタグ（c.cat や イベントのカテゴリ）を先に見るほうが、球団が増えても壊れません。

📌 構造的に気をつけたい点（急がない）

① ガードは「一度日本語になったら二度と更新しない」動きです

Polymarket 側が設問を書き換えても title_ja は古いままになります。 title_en は毎回更新されるので、両者が食い違う瞬間があり得ます。 いまは実害を確認していませんが、設計として記録しておきます。

② 既存行の取得に範囲指定がありません

const { data: existingRows } = await supabase.from('events').select('id, title_ja, category');

現在 events は 137行なので問題ありません。ただ Supabase はサーバ側で行数上限を持ち、 超えた分はエラーではなく黙って返らなくなります。そうなるとガードが一部の銘柄で効かなくなり、 タイトルが静かに戻り始めます。N-20（.limit(100)）とまったく同じ形です。 上限値はこのデータ量では測れませんでした。.range() での明示的なページングを勧めます。
