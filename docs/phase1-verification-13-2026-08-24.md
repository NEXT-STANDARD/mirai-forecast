## ❌ N-50 — 「YES」と呼んでいた数字が YES ではなかった

Polymarket のサブ市場は `outcomes[0]` が必ずしも `"Yes"` ではありません。

```
テニス勝敗市場
  outcomes: ["Lilli Tagger", "Yulia Starodubtseva"]
  prices  : ["0", "1"]
  → 0% は「Tagger が勝つ確率」

サイトの表示（修正前）
  世界オッズ (Polymarket)   YES 0% / NO 100%
```

読者には**何が 0% なのか分かりません。** そして判定文がこうなっていました。

```
質問文「Monterrey Open: Lilli Tagger vs Yulia Starodubtseva」が
公式機関によって公式に確認された場合、YESとして判定されます。
```

**確認しようがありません。** 対戦カードは命題ではないので、確認も否認もできません。

### 実測（有効36件・市場IDで一意に突き合わせ）

```
outcomes[0] == "Yes"   34件  → 「YES x%」は正しい
outcomes[0] != "Yes"    2件  → ❌ Pablo Carreno Busta 0% ／ Lilli Tagger 0%
```

加えて、**日本語タイトルが問いになっていない銘柄**が別に2件ありました。
英語側は対象を名指ししているのに、日本語に出ていません。

```
EPL  title_en: Will Arsenal win the 2026-27 EPL Championship?   → 51% は Arsenal の確率
     title_ja: イングランド・プレミアリーグ 2026-27 優勝クラブ予測  ← Arsenal がない
WTI  title_en: What will WTI hit in August 2026?: ↑ $150?       → 0% は「$150到達」の確率
     title_ja: 2026年8月 WTI原油先物価格の到達水準予測            ← $150 がない
```

判定は推測に頼っていません。**「日本語タイトルが〜か？で終わるか」** で測ると
36件中31件が問いの形、5件がそうでない、という明快な分かれ方をしました。
その5件すべてで「YES x%」に指す先がありませんでした。

### 直し方

```
og:title  【世界の確率「Arsenal」51%】イングランド・プレミアリーグ 2026-27 優勝クラブ予測
アプリ     Lilli Tagger 0% / Lilli Tagger以外 100%
          この確率は「Lilli Tagger」のものです（YES/NOではありません）
判定文     …「Pro Football: 2027 Champion」が公式機関によって確定されます。
          表示している確率は「Los Angeles Rams」が結果になる確率で、
          この市場は YES/NO の二値ではありません。
```

**分岐は `src/utils/probabilityLabel.ts` に集約しました。** 散らばると、
直し漏れた箇所だけが古い枠組みで残ります。事実、og:title を第11回に直したあとも、
**OGP画像とアプリ本体は「YES」のまま**でした。同じことを繰り返さないための集約です。

OGP画像は見出しから誤った `YES` を外すにとどめました。
カードは幅490px・フォント52pxで、**見出しに入るのは約14文字**です。
名前は下段（17px）に置いています。

## 所感

第11回で「多肢イベントは誰の確率か併記する」と直したとき、**og:title だけ直していました**。
同じ画面を構成する OGP画像とアプリ本体は手つかずで、2ラウンド気づいていません。
今回それを見つけられたのは、**OGP画像の中身を初めて見に行ったから**です。
7ラウンドのあいだ、OGPは「HTTPステータスと Content-Type」でしか検査していませんでした。

もうひとつ。今回の3件の測定ミスは、どれも**「値で対象を特定した」**ことが原因でした。
0%の市場が3つある場面で、0%を鍵にして市場を探せば、当然どれかを掴みます。
掴んだものが正しいかは、値では確かめられません。

これは第12回の教訓（検査を足したら検査自身の弱点を探す）の隣にある話だと思います。
**検査の正しさは、検査対象ではなく「鍵の一意性」で決まる**ことがあります。
market_id という一意なキーが手に入るまで、私は同じ場所を3回まわっていました。
