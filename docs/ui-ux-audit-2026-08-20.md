## 00. 総評

このプロダクトの弱点は「デザインの好みが悪い」ことではありません。**2つの構造的な問題**が、良い部分をすべて打ち消しています。

### 1つめ：情報密度という前提が日本語で成立していない

「Cyber-Bloomberg Terminal」というコンセプト自体は明確で、方向性としては筋が通っています。ただしブルームバーグ端末が成立するのは、大型モニタで英数字を扱うからです。同じ密度を漢字かな交じり文で再現しようとした結果、画面上のテキストの 86% が 12px 未満、最頻値は 9.9px になりました。9.9px の漢字は、多くの利用者にとって「読みにくい」ではなく「読めない」水準です。

皮肉なことに、このサイトで最も読みやすいのは一番下のコンプライアンス免責文でした。

### 2つめ：信頼性を売り物にしながら、表示データの一部が実在しない

「実測」「REAL DATA ONLY」「リアルタイム解析済み」というラベルが各所に置かれている一方で、全国ランキングは架空の7人、X シェアカードの「日本の世論」は常に 50% 固定、乖離ランキングの1位は1票から算出されています。

これは UI の問題であると同時に、ブランドの問題です。1人でも気づけば、サイト全体の数字が疑われます。

### 直すべき順番

**捏造データを止める → スタイル基盤を直す → 文字を読める大きさにする**。
この3つを終えるまで、新機能を足す意味はほとんどありません。

## A. データの誠実性

最優先。UI の見た目ではなく、UI が主張している内容の問題です。

### A-1 【P0】「全国クォンツ・リーダーボード」が完全な架空データ。しかも未投票ユーザーの的中率が 75% と表示され、そのまま X にシェアできる

`src/components/ForecastHubPage.tsx:73` の `leaderboardData` は7人分のハードコード配列です。画面の説明文は「全国のトップアナリスト・予報士たちの的中率と活動ランキングです」と、実在の利用者として提示しています。アカウント機能が存在しない以上、全国ランキングは原理的に成立しません。

さらに深刻なのが `accuracy: accuracyRate ?? 75` です。

```js
{ rank: 4, name: 'あなた (You)', accuracy: accuracyRate ?? 75, ... }
```

**投票数0の新規ユーザーにも「的中率 75%」が表示され**、同じ画面の「自慢シェア」ボタンからその数字を添えて X に投稿できます。捏造した実績を利用者本人に発信させる導線になっています。

### A-2 【P0】X シェアカードの「日本の世論」が常に 50% 固定。拡散されるカードすべてが実データではない

`functions/market/[slug].ts` はクローラー向け OGP を生成しますが、`japanProb` は `50` の初期値のまま一度も更新されません。結果、OGP と Twitter Card の説明文は必ず「🇯🇵 日本の世論：YES 50%（ギャップ `|world-50|`%）」になります。

本サイトの成長ループはシェアです。**そのループが毎回、実在しない世論値を配信しています。** A-1 が「サイト内で見つかると痛い」問題なら、これは「サイト外に出て行く」問題です。

### A-3 【P0】看板機能「乖離ランキング」が n=1 と 0 票で成立している

`src/components/SpreadRankingSection.tsx:39`:

```js
const japanYes = ev.japanVotes.total > 0 ? ev.japanVotes.percentYes : 50;
const gap = Math.abs(worldYes - japanYes);
```

実測画面での1位は「パリ・サンジェルマンが CL 制覇するか？ / **86% 乖離**」でした。世界オッズ 14%、日本側は **YES 1票のみ**（＝100%）。差の 86% が「世界のスマートマネーとお茶の間の直感が最も激突しているテーマ」として最上位に出ています。

0票の銘柄も「日本は 50%」と仮定して順位に入るため、**誰も投票していない銘柄が「世論が激突している」と表示され得ます。** 個別ページには「（1票）」と正直に併記されているのに、ランキングカードには件数がありません。同じ数字の扱いが画面間で不一致です。

### A-4 【P0】「Gemini 3.7 Flash リアルタイム解析済み」の実体はキーワード分岐の固定文。API 呼び出しコードはデッドコード

`src/services/polymarketService.ts` の `resolveAiInsight()` は、タイトルに「大谷」「日銀」「ビットコイン」等が含まれるかを `if` で判定し、あらかじめ書かれた文章を返す関数です。`lastUpdated` には文字列 `'Gemini 3.7 Flash リアルタイム解析済み'` がハードコードされています（8箇所）。

実際に Gemini を呼ぶ `src/services/geminiService.ts` は **src 内から一度も import されていません**（呼び出し 0 件）。UI 側は「LIVE ANALYTICS」バッジ付きで表示し、フッターは「Powered by … Gemini 3.7 Flash」と署名しています。

事前生成した分析を使うこと自体は妥当です。問題は**静的なテーブルに「リアルタイム」と書いていること**です。

### A-5 【P1】チャートの始値・高値・安値は合成値。それを「● Polymarket 実測同期済み」と表示している

`src/components/MainTradingChart.tsx` の OHLC は機械的に作られています。

```js
open: Math.max(1, probVal - 1),
high: Math.min(99, probVal + 2),
low:  Math.max(1, probVal - 2),
```

出来高バーも 24h 累計値に係数を掛けた飾りです。株価チャートの体裁を借りているため、利用者は本物の四本値だと解釈します。

### A-6 【P1】「次回注目カタリスト」に過去日付が並んでいる

`src/data/aiInsightsMaster.ts`（38銘柄）に 2024/2025 年基準の日程が 20 箇所残っています。現在 2026-08-20 の画面に、以下が「次回」として表示されます。

- `12月12日：The Game Awards 2024 での電撃ティザー公開有無`
- `11月5日：任天堂 2025年3月期第2四半期決算`
- `2月21日発表：総務省 1月全国消費者物価指数`

### A-7 【P1】コメントが保存されない。投稿してもリロードで消える

`src/components/MarketDetailPage.tsx` の `handleAddComment` は `setComments` のみで、永続化処理がどこにもありません（services 内にコメント関連コード 0 件）。アバターは Unsplash の他人の顔写真が全員共通で固定されています。

加えて `useState(item.comments || [])` は初期化時にしか評価されないため、関連銘柄へ遷移しても**前の銘柄のコメントが残り続けます**。

## B. スタイル基盤の破綻

C 以降の見た目の問題の多くは、ここが原因です。単一の根本原因から派生しています。

### B-1 【P0】Tailwind を導入していないのに Tailwind のクラス名を使っている。全要素の 23% が完全に無スタイル

`package.json` に tailwindcss はありません。CSS は手書きの `index.css` 単体です。にもかかわらず JSX には `flex items-center gap-2 text-[10px] text-slate-400 md:grid-cols-3` のような Tailwind 記法が大量に書かれています。これらは**1行も CSS に存在しません**。

```
クラス付き要素                1,376
うち CSS が 1 件も当たらない    322 (23%)
うち一部のクラスが無効          234 (17%)
────────────────────────────────────
影響を受けている要素            556 (40%)

無効な Tailwind トークン        52 種
無効な独自クラス                32 種
  例: card-vote-btns, modal-title, comment-list, chart-title
```

「使われていない CSS」ではなく「**意図した見た目が出ていない要素**」です。

### B-2 【P0】実害：設計意図と実際の描画のズレ（実測）

| 箇所 | 設計意図 | 実際の描画 |
|---|---|---|
| チャート凡例<br>`MainTradingChart.tsx:434` | 10px / flex 横並び / slate-400 | **16px / block 縦積み / 既定色** |
| ページ下部余白<br>`App.tsx:394` `pb-16` | padding-bottom 64px | **0px** |
| 管理者ボタン<br>`App.tsx:576` | bg-slate-900 / amber | **ブラウザ既定の灰ボタン** |

1行目が、モバイルで「REALTIME MARKET FEED [30D] ● Polymarket 実測同期済み」が巨大な見出しのように崩れて表示される直接原因です。10px の目立たない凡例のつもりが 16px のブロック要素になっています。

2行目はさらに具体的な不具合を生んでいます。モバイルの固定投票バーは高さ 71px。`pb-16` が効かないため回避余白が 0 で、**ページ最下部の 45px が恒久的にバーの下に隠れます**。実際にコピーライト行の後半「Polymarket Public Data & Gemini 3.7 Flash.」が読めません。

### B-3 【P1】`index.css` が 9,512 行の単一ファイル、`!important` 204 個

CSS 変数によるトークン定義（色・角丸・トランジション）は**きちんと設計されています**。問題はその後の運用で、7,500 行目付近に `!important` だらけのモバイル上書きブロックが積み上がっています。後から書いたルールが前のルールと戦っている状態で、1箇所直すと別の箇所が崩れます。

内訳として、管理コンソール専用のスタイルが **3,275 行（全体の 34%）** を占めています。`/admin` は localhost 限定なのに、全訪問者に配信されています。

### B-4 【P3】`App.css` が Vite テンプレートの残骸のまま

184 行の `.counter` / `.hero .vite` 等。どこからも import されていません。`README.md` も Vite テンプレートの英語原文のままです。

## C. 可読性・日本語組版

日本語サイトとして、ここが最も影響範囲の広い問題です。

### C-1 【P0】画面上のテキストの 86% が 12px 未満。最頻値 9.9px（257箇所）

実測フォントサイズ分布（トップページ・可視テキストノード 675 件）:

```
 9.3px  ▓▓▓▓▓▓                       66
 9.9px  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   257  ← 最頻値
10.4px  ▓▓▓▓▓                        54
10.9px  ▓▓▓▓▓▓▓▓▓▓▓                 117
11.5px  ▓▓▓▓▓▓                       69
12px～  ▓▓▓▓▓▓▓▓                     95

12px 未満: 580 / 675 = 86%
```

ラテン文字なら 10px でも判読できます。漢字は画数が多く、同じサイズでは字形が潰れます。日本語の本文は 16px 前後、補助情報でも 13〜14px が下限というのが一般的な指針です。**9.9px は補助情報のサイズではなく、判読不能のサイズです。**

これは装飾の問題ではなくコンセプトの帰結です。ブルームバーグ端末の密度を日本語で再現しようとすると、必ずここに突き当たります。**密度を捨てるか、日本語を捨てるかの二択**で、前者を選ぶべきです。

### C-2 【P1】コントラスト WCAG AA 不合格が 186 箇所（28%）。主犯は `--text-muted: #64748b`

ダーク背景に対して 3.4〜4.05:1。AA の基準 4.5:1 に届きません。カテゴリタグ、日付、出来高、パーセント記号、「いいえ、一般の訪問者です」など、**低優先度として意図的に薄くした要素がまとめて落ちています**。

単純に `--text-muted` を `#8A96A8` 程度まで持ち上げるだけで大半が解決します。C-1 の文字サイズ拡大と同時に行えば、階層の見え方は保てます。

### C-3 【P1】禁則処理の設定がゼロ。見出しが「日／本の世論」で改行される

`index.css` 内の出現数:

| プロパティ | 出現数 |
|---|---:|
| `word-break` | 0 |
| `line-break` | 0 |
| `overflow-wrap` | 0 |
| `text-wrap` | 0 |

実機（375px 幅）のオンボーディング見出しで `世界のスマートマネー vs 日` / `本の世論` と、**「日本」が分断されて改行されました。** カラム幅が狭い箇所が多いため、同様の破綻が各所で起きています。

対策は1箇所です。

```css
body {
  word-break: auto-phrase;
  line-break: strict;
  overflow-wrap: break-word;
}
h1, h2, h3, h4 { text-wrap: balance; }
```

### C-4 【P2】画像が1枚もない。`iconUrl` は型に定義されているが未使用

実測で `<img>` 0 件、background-image 0 件。`MarketItem.iconUrl` はどこからも参照されていません。極小テキストと絵文字だけで 84 銘柄が並ぶため、視覚的な取っかかりがなく、走査性が著しく低い状態です。

## D. 体験設計・ナビゲーション

### D-1 【P0】初回訪問で4つのオーバーレイが連続。z-index が逆転していて操作不能になる

```
0.0s  OnboardingModal      z-index  100
1.5s  MikeNoticePopup      z-index 1000  ← モーダルの上
3.0s  PwaInstallBanner     z-index 1000  ← モーダルの上
 +    ComplianceBanner（フッター常設）
```

主役であるオンボーディングモーダルが最背面にあるため、**実機で「スキップ」「次へ」ボタンが後発のポップアップに覆われ、押せません。** Mike ポップアップを閉じると、今度は PWA バナーが同じ位置に出て再び覆います。

閉じるボタンは 22×22 / 19×22 / 21×24px。WCAG 2.5.8（AA）の最小 24×24px を下回っています。

### D-2 【P1】全訪問者に「あなたはマイク・エイドリン氏ですか？」を出している

初回訪問の一等地に、Polymarket Japan 代表1名に宛てた公開書簡の案内が出ます。主 CTA（金色）が「手紙を読む」、離脱側が低コントラストの「いいえ、一般の訪問者です」。**1人のための導線が、全員のデフォルトになっています。**

公開書簡というアイデア自体は面白いので、ヘッダーの導線は残しつつ、初回モーダルからは外すのが妥当です。

### D-3 【P1】「投票で解禁」ゲートが全カードに掛かり、サイトの価値が一度も見えないまま離脱する

初回訪問者の画面は、日本世論の欄がすべて「🔒 投票で解禁」で埋まります。バイアス回避という設計意図は理解できますが、**OGP で「比較・可視化」と約束したものが、着地後に1件も見えない**状態です。

折衷案：**1件だけ解禁済みのサンプルを見せる**（この画面で何が起きるかを体験させる）→ 残りはゲート、という形にすれば、意図を保ったまま価値が伝わります。

### D-4 【P0】モバイルの固定投票バーが、画面に映っていない別銘柄に投票する

固定バーの対象は `currentFocusedEvent`（ターミナルで選択中の銘柄）で固定されています。利用者が下部のカードグリッドまでスクロールすると、**画面にはカードの YES/NO、最下部には別銘柄の YES/NO が同時に並びます。**

実機で確認した状態：画面には「統一ロシアは次期下院選で…」のカード、固定バーは「ホルムズ海峡の通航量は…」。大きく目立つ後者を押すと、読んでいない銘柄に投票が入ります。**本アプリで最も誤操作リスクが高い箇所です。**

### D-5 【P2】カードを押すとページ最上部へ強制スクロールされる

`src/App.tsx:489`。グリッド最下部のカードをクリックすると `window.scrollTo({top:0})` でターミナルまで引き戻されます。「押した → 上に飛ばされた」の因果が画面上に見えないため、不具合と受け取られます。

### D-6 【P2】カテゴリナビが同一ページに2セット。定義も2箇所にコピペされている

ヘッダーの `categories`（`Header.tsx:49`）とグリッドの `UNIFIED_CATEGORIES`（`AllMarketsGrid.tsx:30`）は同じ内容の別配列です。利用者から見れば同じタブが2つあり、どちらを押せばよいか分かりません。

あわせて、ソートの `'newest'` は型にあるだけで選択肢に無く、選ばれても `return 0` の空実装です。クイック検索タグ（大谷翔平 / Switch 2 / GPT-5 …）もハードコードで、鮮度管理の仕組みがありません。

### D-7 【P2】モバイルではヘッダー機能の大半が消え、「使い方」に二度と到達できない

`hide-on-mobile` / `hide-on-xs` により、「使い方」「問いを提案」「AI連携」「to Mike」がモバイルで非表示になります。代替のメニューはありません。

とくに「使い方」はオンボーディング再表示の唯一の入口です。**初回モーダルを一度閉じたモバイル利用者は、説明に永久に戻れません。** また各所で `title` 属性を唯一のラベルにしていますが、タッチ端末では表示されません。

## E. アクセシビリティ

### E-1 【P1】モーダル7種すべてに Esc・フォーカストラップ・`role="dialog"` が無い

Onboarding / Event / OgpPreview / Embed / DataExport / ProposeTopic / MyForecast のいずれにも、`Escape` ハンドラ、`aria-modal`、フォーカス移動・復帰の実装がありません（該当コード 0 件）。キーボード利用者はモーダルを開いた瞬間に背後のページへタブが抜け、閉じる手段を失います。

### E-2 【P1】タップ領域 124 個中 112 個が 44px 未満。最小は 19px

| 要素 | サイズ |
|---|---|
| 時間軸ボタン (1H/24H/7D) | 27×19 |
| 「＋ 問いを提案」 | 79×22 |
| 「個別ページ」 | 79×21 |
| 同期ボタン | 27×24 |
| カテゴリタブ | 73×28 |
| ヘッダー各ボタン | 77×32 |

19px はスマートフォンでの確実な操作が難しい水準です。WCAG 2.5.8（AA）の 24×24px 下限も割っています。

### E-3 【P2】トップページに `h1` が存在しない。見出し階層も飛んでいる

実測した見出し構造は `h2 → h3 → h4` で始まり、`h1` がありません。`h1` があるのは詳細ページ・書簡・AI連携・予報士ハブ・管理画面のみです。ロゴは `<div onClick>` で、リンクでもボタンでもありません（`Logo.tsx:17`）。

### E-4 【P2】クリック可能な非ボタン要素が 27 箇所。キーボードで操作できない

スクリーナーの `<tr onClick>`、カードの `<div onClick>` など。`tabIndex` 0 件、`onKeyDown` 0 件、`role=` 0 件。`aria-label` はボタン 138 個に対し 10 個です。

### E-5 【P2】`prefers-reduced-motion` 未対応。グリッチ・点滅アニメーションを多用している

`@keyframes` は 11 種（`cyberGlitch`、`rgbChromaWave`、`laserShimmer`、`rgbBorderFlow` ほか）。`animate-pulse` 相当の点滅も各所にあります。減光設定を尊重するメディアクエリは1件もありません。前庭障害・光過敏の利用者に配慮が必要です。

`:focus-visible` の定義も 0 件で、キーボードフォーカスの視認手段がありません。

## F. 実装・パフォーマンス

### F-1 【P1】単一チャンク 700kB。管理コンソール一式が全訪問者に配信されている

```
dist/assets/index.js   700.61 kB  (gzip 201.04 kB)
dist/assets/index.css  139.74 kB  (gzip  23.51 kB)
コード分割 (lazy/import())   0 箇所

同梱されている非公開ページ:
  AdminConsolePage.tsx   1,394 行
  管理コンソール CSS      3,275 行（index.css の 34%）
```

`React.lazy` が1箇所も無いため、localhost 限定の `/admin`、書簡ページ、AI 連携ページ、全モーダルが初回ロードに含まれます。

また `dist` に `test_ogp_output.png`（96kB）を含む X 用画像 320kB が配信されています。

### F-2 【P1】30秒ポーリングが2系統。バックグラウンドでも止まらない

`App.tsx:297`（全銘柄）と `MainTradingChart.tsx:59`（価格履歴）がそれぞれ 30 秒間隔で走ります。`visibilitychange` / `document.hidden` のガードは 0 件です。

タブを開いたまま放置すると、**Polymarket の公開 API と Supabase を無期限に叩き続けます。** ブラウザから直接叩いているため、キャッシュ層もレート制御もありません。Cloudflare Functions が既にあるので、そこに集約するのが自然です。

加えて、30秒ごとに `isRefreshing` が true になり、ヘッダーの同期アイコンが利用者の操作と無関係に回り続けます。

### F-3 【P2】ルーティングが真偽値5個の手組み。Hooks のルール違反もある

`isAdminOpen` / `isLetterPageOpen` / `isAiConnectorOpen` / `isForecastHubOpen` / `detailMarketId` の5状態が排他であるべきなのに、遷移関数のたびに4つを手で `false` にしています（`App.tsx:127-182`）。1つ書き忘れれば2ページが同時表示されます。

さらに `App.tsx:34` で、**すべての `useState` より前に `if (embedSlug) return ...` の早期 return** があります。現状は動作しますが Rules of Hooks 違反で、条件が動的になった瞬間に壊れます。単一の `route` 状態、または react-router へ寄せるべき箇所です。

### F-4 【P2】`.gitignore` の `*.json` が `manifest.json` を巻き込んでいる

`.gitignore:32` の一括除外により、`public/manifest.json` と `public/data/ai_insights.json` が **git 管理外**です（`git check-ignore` で確認済み）。クリーンな clone からビルドすると PWA マニフェストが欠落します。

### F-5 【P3】未使用の重量級依存が dependencies に6つ

`three`、`googleapis`、`sharp`、`twitter-api-v2`、`@google-analytics/data`、`clsx` は src から一度も import されていません（`node_modules` は 444MB）。スクリプト用途のものは devDependencies へ移すのが適切です。

あわせて、`PwaInstallBanner.tsx` の `Notification.permission` 初期化は早期 return の後ろにあり、初回訪問者では実行されません。通知許可済みでも「的中通知をON」が出続けます。

## G. SEO・法務

### G-1 【P1】Googlebot に本文ゼロのスタブを返している。自己参照の meta refresh 付き

`functions/market/[slug].ts` は User-Agent で分岐し、正規表現に **`googlebot` が含まれています**。Googlebot が受け取る HTML の `<body>` は次の1行だけです。

```html
<meta http-equiv="refresh" content="0;url=${url.href}">   <!-- 自分自身へ -->
<body>
  <p>リダイレクト中... <a href="...">タイトル</a></p>
</body>
```

sitemap.xml に登録した **179 URL すべてが、検索エンジンから見て実質的に空**です。しかも遷移先が同一 URL のため、meta refresh を追うクローラーは同じスタブに戻ります。利用者とクローラーに別内容を返す構造は、クローキングと判定されるリスクもあります。

OGP 生成は残し、**ボット判定は Twitterbot 等の SNS クローラーに限定**、検索エンジンには実コンテンツを返す（プリレンダー等）方針に変えるべきです。

### G-2 【P1】利用規約とプライバシーポリシーのページが存在しない

フッターの見出しは「コンプライアンス及び**利用規約**に関する重要事項」ですが、規約本体もプライバシーポリシーもリンクがありません。実際には GA4（`G-B4LW25DWX9`）を読み込み、Supabase に投票・端末種別・リファラを送信しています。

賭博法・公選法への配慮を前面に出しているサイトとしては、**この2ページの欠落が最も目につく穴**です。技術的には最も安く塞げます。

### G-3 【P3】日本語化されていない銘柄と誤カテゴリが混在している

実画面で確認：

- `What will WTI Crude Oil (WTI) hit in August 2026?`
- `Pro Football: 2027 Champion`
- `EWC 2026 CS2: Winner`
- `EPL: 2027 Champion`

が英語のまま表示されています。また `Pro Football: 2027 Champion` と `EWC 2026 CS2: Winner`（e スポーツ）が**「📊 経済・金利・暗号資産」に分類**されています。歩み値には銘柄名を解決できなかった `銘柄 #814068` `銘柄 #official` が流れています。

## ＋ 残すべき点

作り直しではなく修正で進められる理由です。土台は悪くありません。

| 項目 | 内容 |
|---|---|
| **コンセプトが一言で言える** | 「世界のリアルマネー確率 × 日本の世論」は、説明不要で伝わる強い軸。ここは動かす必要がない |
| **デザイントークンが定義されている** | 色・角丸・トランジションが CSS 変数で整理済み。C-1 / C-2 の修正は変数の値を変えるだけで広範囲に効く |
| **モバイルのカードグリッドは良い** | 本文が読めるサイズで、YES/NO も十分に大きい。**ここを全体の基準にすべき** |
| **歩み値は本物のデータ** | LiveTape は Supabase の実投票ログと実出来高を表示。A 群の中でここだけは表示と実体が一致している |
| **法令配慮の設計思想** | 公選法ブラックアウト、非賭博の明示は、日本市場で先に手を打つべき点を正しく押さえている |
| **型安全** | `tsc -b` がエラー 0 で通る。型定義も丁寧で、リファクタリングの土台がある |
